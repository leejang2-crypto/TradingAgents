# 계좌·기간별 수익률 대시보드

## 사용 방법

실행 중인 프로그램을 종료하고 기존 `Start-DryRun.command` 또는 `Start-Live.command`를
다시 실행합니다. 기존 Tailscale 대시보드 주소로 접속하고 로그인한 뒤 **계좌 · 수익률**에서:

1. 모의투자 또는 실투자를 선택합니다. 조회 모드는 실제 매매 실행 모드를 변경하지 않습니다.
2. **조회**를 누릅니다. 로그인 세션을 사용하므로 별도 토큰 입력은 없습니다.
3. **일 / 주 / 월 / 년**과 수익률 조회 기준일을 선택합니다.
4. 최신 시세·Toss 자료를 가져오려면 **최신 자료 조회**를 누릅니다.

최초 계정 등록은 `Setup-Web-Login.command`로 진행합니다.
[웹 로그인·수동 실행 안내](web_login_and_manual_runs.md)를 참고하세요.

모니터 서버가 켜져 있으면 현재 실행 모드의 계좌를 5분마다 조회·기록합니다.
브라우저는 조회 후 30초마다 저장된 결과를 읽습니다. 같은 계좌의 외부 갱신은 60초 내
반복하지 않습니다. 브라우저가 닫혀도 서버가 실행 중이면 평가 기록을 수집합니다.

## 모의계좌

이번 변경부터 `main.py`의 당일 모의 주문은 로컬 가상 체결 장부를 사용합니다.
실제 Toss 주문 생성 API는 호출하지 않습니다. 시세는 Toss `GET /api/v1/prices`를 사용하므로
공용 `.env`의 `TOSS_CLIENT_ID`, `TOSS_CLIENT_SECRET`이 필요합니다. 모의계좌에는 실제
Toss 계좌 식별자가 필요하지 않습니다.

- 최초 계좌 생성 시 웹에 저장된 자본금(기본 1천만 원)을 초기 현금으로 사용합니다.
- 평균 매입원가, 현금, 보유수량, 수수료·세금 가정, 실현/미실현손익을 기록합니다.
- BUY는 현금과 주문 예산 내에서 정수 주식 수량을 계산합니다. SELL은 실제 가상 보유수량 이내만 가능합니다.
- 종목·통화·가격·시세 시각을 검증합니다. 체결은 2분 이내 시세만 허용하고, 평가액 계산은 기존 15분 유효기간을 사용합니다.
- 시세 조회 실패·현금 부족·보유수량 부족이면 `SIMULATED_REJECTED`로 기록합니다.
- 가상 체결은 `SIMULATED_FILLED`이며, 거래소의 실제 체결 확인을 의미하지 않습니다.
- 같은 실행 ID를 다시 전달해도 가상 체결은 한 번만 장부에 반영합니다.
- 웹에서 자본금을 변경해도 기존 계좌 현금을 초기화하거나 증액하지 않습니다. 기존 장부는 보존합니다.
- 과거 날짜 분석과 구형 실행 스크립트는 기존 주문 의도 기록 경로를 유지합니다.

**기존 `RECORDED` 주문 이력은 체결가·체결 여부가 없어 새 계좌에 소급 반영하지 않습니다.**
TossTrading 프로젝트의 모의계좌와도 별개입니다. 새 장부 생성 이후부터 수익률 이력이 쌓입니다.

### 보유·현금 연동

- 자동 단타 매수 수량은 기존 투자금·위험 한도와 **실제 모의 현금으로 수수료까지 감당할 수 있는 수량** 중 작은 값으로 정합니다. 웹 설정 자본금이 계좌 잔고보다 크더라도 잔고를 넘겨 매수하지 않습니다.
- 보유 종목 추가 매수와 당일 청산 종목 재진입은 차단합니다. SELL 판단은 관리 중인 실제 보유 수량을 전량 매도하고, 미보유 종목이면 주문하지 않습니다.
- 분석 직전 현금 잔고·해당 종목 수량·평균 매입원가·총 보유 종목 수를 의사결정 프롬프트에 전달합니다. 실행 직전 다시 확인하므로 분석 도중 계좌가 바뀌어도 이전 상태를 그대로 주문하지 않습니다.
- 보유 관리기는 처음 시작할 때뿐 아니라 이후 추가된 모의 체결도 장부에서 동기화합니다. 이미 반영된 체결은 중복 계산하지 않습니다.
- 새 체결에는 현금과 보유 수량의 전후 값, 체결 금액, 수수료·세금과 실현손익을 남깁니다. 기존 이력에 없던 값은 추정하여 채우지 않습니다.

### 거래 내역 표시

**거래 내역 → Recent Paper Trades**는 SQLite 계좌 장부에 있는 체결만 `가상 체결 · 계좌 반영`으로 표시합니다. 구형 JSONL에 `FILLED`로 기록되어 있어도 대응하는 모의 장부 체결이 없으면 `주문 계획만 기록 · 계좌 미반영`으로 표시합니다. 파일 원문은 수정하지 않습니다. 같은 체결이 JSONL에 여러 번 있어도 표시를 중복하지 않으며, JSONL 기록이 빠져도 장부 체결은 표시합니다.

주문 금액/수량과 실제 체결 수량·체결가·처리 후 현금·보유 수량을 분리했습니다. 계좌 주문 표에는 수수료, 세금, 실현손익과 보유 수량 전후 값도 표시합니다. 과거 주문 계획을 임의로 체결로 바꾸거나 잔고를 초기화하지 않습니다.

### 시뮬레이션 한계

잔고·수량·비용·중복 체결 방지와 지정가 제한을 검증하지만 실제 거래소 체결 엔진은 아닙니다. 최신 시세와 설정 슬리피지를 바탕으로 즉시 전량 체결 또는 거절을 계산합니다. 호가 대기 순서, 주문 규모에 따른 시장 충격, 부분 체결, 결제일별 출금 가능 금액은 재현하지 않습니다. 지정가를 충족하지 못하면 체결하지 않으며 대기 주문을 만들어 두지 않습니다. 매도 대금은 모의 현금에 즉시 반영됩니다.

비용 가정은 기본 0이며 실제 증권사 비용을 뜻하지 않습니다. 최초 계좌 생성 전에 공용 환경에
아래 소수 비율 값을 지정할 수 있습니다. 생성 후 가정과 자본은 장부에 고정됩니다.

```text
TRADINGAGENTS_PAPER_FEE_RATE=0
TRADINGAGENTS_PAPER_SELL_TAX_RATE=0
TRADINGAGENTS_PAPER_SLIPPAGE_RATE=0
```

## 수익률 계산

`총 평가자산 = 현금 + 보유주식 평가금액`

`기간 수익률(%) = (마지막 기록 평가자산 - 기준 기록 평가자산) / 기준 기록 평가자산 × 100`

입출금 기능은 없으며 초기 자본은 고정입니다. 매입원가에 매수 비용을 포함하고, 실현손익에서
매도 비용을 차감합니다. 평가손익은 가상 보유주식의 평가액과 남은 원가의 차이입니다.

일은 한국 날짜, 주는 월요일 시작, 월·년은 달력 기준입니다. 이전 기간의 마지막 평가를 기준으로
현재 기간의 마지막 평가와 비교합니다. 최근 최대 60개 관측 기간을 표시합니다.
첫 기간 또는 기준 평가일이 떨어져 있는 기간에는 `부분 기간`을 표시합니다. 표의 시작·종료
평가 시점을 함께 확인하세요. 정확한 거래소 종가 기준 수익률이나 입출금 보정 TWR은 아닙니다.

기준일보다 미래의 기록은 제외합니다. 기록하지 않은 과거 평가금액은 만들어 넣지 않습니다.
시세가 없거나 지연되면 현재 평가액·미실현손익은 `-`로 표시합니다. 이전의 유효한 평가 기록은
그 당시 시점 그대로 보존합니다. 따라서 장 종료 후에는 보유수량·현금은 보이지만 현재 평가액이
미확인 상태일 수 있습니다. 조회 기준일은 수익률 표에 적용되며 보유주식은 현재 장부입니다.

## 실투자: 지원 범위

공식 [Toss OpenAPI 명세](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json)
버전 1.2.15를 확인하여 아래 조회만 연결했습니다.

| API | 표시 항목 |
|---|---|
| `GET /api/v1/holdings` | 국내·미국 보유종목, 수량, 매입가, 현재가, 평가액, 평가손익, 보유주식 수익률·당일 변동률 |
| `GET /api/v1/buying-power` | KRW·USD 각각의 현금 기반 매수 가능 금액 |
| `GET /api/v1/orders` | 최근 30일 주문의 처리 상태와 체결 수량·평균 체결가 |

`TOSS_ACCOUNT_SEQ`도 필요합니다. 실제 계좌 조회는 주문 생성·정정·취소를 호출하지 않습니다.
국내·해외 금액은 통화를 섞어 합산하지 않습니다. 주문 조회는 OPEN과 CLOSED 첫 페이지이며
CLOSED 추가 페이지가 있으면 화면에 표시합니다. API 오류는 항목별로 표시하고 0원으로 대체하지 않습니다.

**매수 가능 금액은 현금 잔고가 아니며, 보유주식 평가수익률은 계좌 전체 수익률이 아닙니다.**
명세에는 월·주·년 계좌 수익률이나 입출금 이력을 조회하는 전용 API가 없습니다. 종료 포지션,
외부 입출금, 실제 현금 잔고를 모르는 상태에서 계좌 기간 수익률을 계산하지 않고 `API 미지원`으로
표시합니다. 현재 보유주식의 당일 변동률을 주·월·년으로 단순 복리 계산하지 않습니다.

Toss는 같은 client의 새 토큰 발급 시 이전 토큰을 무효화합니다. 대시보드·시세·주문 클라이언트는
프로세스 안에서 토큰을 공유합니다. 외부 프로세스에 의해 무효화되면 GET만 1회 재인증하며,
주문 POST는 자동 재전송하지 않습니다. 별도 TossTrading 프로세스와 같은 API client를 동시에
사용하면 토큰이 서로 무효화될 수 있으므로 동시 운용에 주의하세요.

## 저장 및 검증

```text
/Users/leejang2/Project/TradingAgents/.local/accounts/paper.sqlite3
/Users/leejang2/Project/TradingAgents/.local/accounts/live_<계좌별해시>.sqlite3
```

실계좌 변경 시 조회 캐시를 분리합니다. `.local`에는 금융 기록이 있으므로 외부에 공개하지 마세요.
모의 체결은 기존 주문 JSONL 및 경험 실행 ID와 연결합니다. 경험 메모리는 아직 실제 손익 기반
자동 재훈련으로 전환하지 않았습니다. 원클릭 실행·13시 회차·실주문 경로는 그대로 유지됩니다.

검증은 수익률/원가/잔고 계산, 중복 체결 방지, 시세 오류·권한 검사, 공식 스키마 기반 모의 Toss 응답,
PC/모바일 브라우저 테스트로 수행했습니다. 실제 금융 계좌 조회나 실주문 전송으로 검증하지 않았습니다.
