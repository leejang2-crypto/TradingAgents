| StockTwits 테스트가 Python 3.10에서 수집 단계 오류 | 예외 객체의 명시적 테스트 ID 지정 |

주문 기록 후 재실행되는 중복을 피하기 위한 동작입니다. 다음 거래일에는 다시 실행합니다.
파일 잠금은 수정된 버전끼리 적용됩니다. 이전 버전 프로세스는 종료 후 새 버전을 시작하세요.

## 웹에서 LLM 선택

실행 중인 프로그램을 `Ctrl+C`로 종료하고 다시 실행합니다.

```bash
cd /Users/leejang2/Project/TradingAgents
/Users/leejang2/Project/.venv/bin/python main.py --monitor --monitor-host tailscale --monitor-port 8765
```

휴대폰에서 기존 Tailscale 접속 주소를 열고 `Trading Settings`의 `LLM 설정`을 사용합니다.

1. `실행 제공자`에서 OpenAI 전체 / Ollama 전체 / 역할별 혼합을 선택합니다.
2. OpenAI와 Ollama의 quick/deep 모델을 지정합니다. 직접 모델 ID 입력도 가능합니다.
3. 혼합 모드에서는 각 에이전트의 제공자를 선택합니다.
4. 모니터 토큰을 입력하고 `설정 저장`을 누릅니다.

`뉴스만 로컬로 설정`은 혼합 모드를 선택하고 뉴스만 Ollama로 배정하는 단축 명령입니다.
이 버튼을 누른 후에도 `설정 저장`을 해야 적용됩니다.
`로컬 모델 목록 확인`은 Ollama에서 이미 설치된 모델을 읽으며 모델을 다운로드하지 않습니다.
확인된 설치 모델은 `qwen3:8b`, `gemma3:12b`입니다.

설정은 `.local/config/trading_settings.json`에 저장합니다. 진행 중인 분석은 변경하지 않고
다음 분석 실행부터 반영합니다. 당일 이미 실행을 마쳤으면 새 설정은 다음 거래일에 쓰입니다.
시작 시 명시한 CLI 설정이 저장값보다 우선하며, 이후 웹에서 저장한 설정으로 변경할 수 있습니다.
OpenAI 키와 Ollama 모델 파일은 웹에서 변경하거나 노출하지 않습니다.

## 비용 절감 분담

| 역할 | 시작 권장 설정 | 목적 |
|---|---|---|
| 뉴스 근거 선택/분류 | Ollama quick = qwen3:8b | 이 단계의 OpenAI 호출 제거, 원문 근거만 전달 |
| 시장 분석/강세·약세 리서치/트레이더/위험 토론 | OpenAI quick | 로컬 다단계 대기 시간 증가 제한 |
| 리서치 매니저/포트폴리오 매니저 | OpenAI deep | 최종 종합 판단과 구조화된 출력 |
| 전부 로컬로 실험할 때 | quick=qwen3:8b, deep=gemma3:12b | 외부 LLM 호출 없이 실행, 대기 시간은 길어질 수 있음 |

OpenAI 기본 모델은 기존 `gpt-5.5`를 유지합니다. quick에 계정에서 접근 가능한 더 저렴한 모델을
지정하는 방법도 있습니다. UI의 모델 ID 제안은 해당 계정의 사용 권한을 보증하지 않습니다.
심리·재무 분석은 기본 한국 종목 runner에서 실행하지 않으며 화면에도 현재 미사용으로 표시합니다.
Gemma3는 현재 설치 정보에서 도구 호출 기능이 없으므로 시장 분석용 quick에는 qwen3를 사용하세요.
뉴스만 로컬인 경우 deep=gemma3를 설정해 두어도 호출되지 않으므로 두 로컬 모델을 동시에
메모리에 올릴 필요가 없습니다. 외장 SSD는 기존 Ollama 설정대로 사용합니다.

## 실제 로컬 호출에서 확인한 문제와 보완

첫 자유서술형 시험에서는 qwen3:8b가 종목 코드에 없는 회사명을 만들어 냈습니다.
그 결과를 성공으로 처리하지 않고 뉴스 로컬 경로를 원문 인용 선택/분류 방식으로 바꿨습니다.

- Python이 종목과 조회 기간을 고정합니다.
- 네이버 검색 결과의 제목/요약문을 최대 14,000자로 제한하고 한 번 호출합니다.
- 모델은 기사 번호, 원문 그대로의 인용문, 촉매/위험/불확실/중립 분류만 JSON으로 반환합니다.
- Python이 인용문이 지정한 기사에 실제 있는지 확인하고 출처와 날짜를 붙입니다.
- 다른 종목, 원문에 없는 문장, 잘린 JSON/토큰 제한 출력은 오류로 처리합니다.
- 회사명이나 설명 등 검증하지 않은 추가 생성 필드는 보고서에 넣지 않습니다.
- 원문 검증은 뉴스의 진위나 분류 판단의 정확성까지 보증하지 않습니다.
- 이후 리서치/트레이더/위험/포트폴리오 단계가 `news_report`를 함께 사용합니다.

초기 버전은 로컬 실패 시 자동 전환하지 않았습니다. 2026-09-29부터 역할 혼합 모드의
뉴스 근거 검증 실패에는 아래의 제한된 복구 절차를 적용합니다.
OpenAI 뉴스 분석을 선택하면 기존 글로벌 뉴스/FRED/예측시장 도구 흐름을 사용합니다.
따라서 두 모드의 뉴스 분석 범위가 동일하지 않으며 비용 절감률도 실제 기사 수와 다른
에이전트 사용량에 따라 달라집니다. 고정 절감률은 산출하지 않았습니다.

반복 프롬프트의 공통 앞부분을 유지하면 OpenAI의 prompt caching도 활용할 수 있지만,
캐시 적중과 비용은 모델 및 요청 형태에 따라 확인해야 합니다.
[OpenAI 공식 문서](https://developers.openai.com/api/docs/guides/prompt-caching)

로컬 모델 목록과 OpenAI 호환 주소는 Ollama의 공식 API를 사용합니다.
[모델 목록 API](https://docs.ollama.com/api/tags),
[OpenAI 호환 API](https://docs.ollama.com/api/openai-compatibility)

## 뉴스 검증 실패 복구 (2026-09-29)

역할 혼합 모드에서 뉴스 담당이 Ollama인 경우에만 적용합니다.

1. 로컬 모델이 종목 코드와 기사/문장 번호를 선택합니다.
2. 코드 불일치, 없는 번호, 잘린 응답 등 검증 실패 시 로컬 모델에 한 번 재요청합니다.
3. 재검증도 실패하면 설정된 OpenAI quick 모델로 해당 뉴스 선택만 한 번 대체합니다.
4. OpenAI에도 동일한 종목/원문 카탈로그와 검증을 적용합니다. 이마저 실패하면 해당
   종목 분석을 오류로 종료하고 주문 단계로 넘기지 않습니다.

실패한 모델의 원문 응답은 재요청 프롬프트에 넣지 않습니다. 기사 재수집이나 전체
에이전트/매매 사이클 재실행도 하지 않습니다. 정상 로컬 응답에는 추가 요청이 없습니다.
각 선택 요청의 출력 한도는 1,600토큰입니다. OpenAI 대체는 논리적 분석 호출 1회이며,
통신 오류에 대한 SDK 내부 재시도는 기존 `llm_max_retries` 설정을 따릅니다.

Ollama 전용 모드는 로컬 재시도 후 오류 처리하며 유료 외부 호출을 하지 않습니다.
뉴스 수집 실패, 빈 카탈로그, 로컬 연결 오류/타임아웃은 이 검증 복구의 대상이 아닙니다.
Python 설정의 `news_openai_fallback=False`로 혼합 모드의 유료 대체도 끌 수 있습니다.
OpenAI를 뉴스 담당으로 직접 지정한 기존 도구 기반 분석 경로는 변경하지 않습니다.

분석 보고서 첫 줄에 실제 경로와 검증 상태를 표시합니다. 실행 요약의 `newsExecution`,
그래프 상태 기록의 `news_execution`에는 제공자, 모델, 시도 번호, 실패 이유 및
`fallbackUsed`를 저장합니다. 실패한 종목의 실행 요약에도 복구 시도 기록을 남깁니다.
JSON 형식 자체가 근거의 정확성을 보장하지 않으므로 제공자와 무관하게 검증합니다.
[OpenAI JSON 모드 문서](https://developers.openai.com/api/docs/guides/structured-outputs)

실행 중인 프로그램을 종료하고 재시작해야 새 코드가 적용됩니다. 기존
`completed-with-errors` 기록은 소급 변경하지 않으며 다음 분석부터 적용합니다.
당일 전체 매매를 자동 재실행하지 않습니다. 모의투자/실투자 실행 상태와 주문 이력은
복구 기능 배포만으로 변경하지 않습니다.

이번 추가 기능은 모의 LLM 응답으로 재시도, 대체, 엄격한 검증 유지, 중단 요청 처리를
시험했습니다. 유료 LLM 실호출이나 실제 주문으로 시험하지 않았습니다.
