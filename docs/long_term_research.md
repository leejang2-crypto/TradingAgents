# 중장기 종목 탐색

## 실행

대시보드의 **중장기** 탭에서 보유 관점, 탐색 종목, LLM을 선택하고 **중장기 탐색 실행**을 누릅니다. 결과는 이 탭에서만 표시되며 자동 매수, 기존 보유 편입, 단타 후보 변경을 하지 않습니다. 기존 실행 프로그램을 재시작하면 탭이 추가됩니다.

- 기본 관점: 3~12개월. 1~3개월 또는 1~3년도 선택 가능합니다.
- 기본 종목: **코스피100 구성종목 전체 100개**. 입력란을 비우면 기준일이 확인된 구성목록 전체를 분석합니다. 시가총액 상위 100개, KRX100, 코스피200을 대신 사용하지 않습니다.
- 직접 입력: `005930.KS, 000660.KS`처럼 쉼표 또는 공백으로 구분합니다. 최대 100개이며 `.KS`를 명시합니다. 구성목록에 없는 종목이나 코스닥 종목은 분석을 시작하지 않습니다.
- 기본 LLM: 미사용. 정량 탐색만으로 동작합니다.
- OpenAI/Ollama 선택 시 기존 설정의 해당 제공자 quick 모델을 실행 시점에 복사합니다. 단타 설정을 변경하지 않습니다. OpenAI는 비용, Ollama는 메모리/연산 사용을 확인한 뒤 실행합니다.
- 실행은 비동기이며 창을 닫아도 계속됩니다. **탐색 중단**은 해당 연구 작업만 중단합니다. 저장된 최근 20회 결과를 메뉴에서 다시 열 수 있습니다. 더 오래된 파일도 삭제하지 않습니다.

## 코스피100 구성목록

실행 시 당일 확인한 구성목록 캐시를 사용하고, 없으면 KRX 지수 구성종목 조회를 시도합니다. 지수 식별자는 `1034` (`indIdx=1`, `indIdx2=034`)입니다. 주말을 건너뛰고 최근 10일 범위에서 목록이 있는 기준일을 찾습니다. HTTP 오류나 접근 제한을 우회하지 않습니다. 이 환경에서 공식 공개 요청은 HTTP 403으로 차단되었으므로 CSV 등록이 필요할 수 있습니다.

1. [KRX 정보데이터시스템](https://data.krx.co.kr/contents/MDC/MAIN/main/index.cmd)에서 **지수 구성종목**을 검색하고 **코스피 100**을 선택합니다. 필요하면 KRX 사이트에 직접 로그인합니다.
2. 최근 기준일의 전체 구성종목을 CSV로 내려받습니다. 종목코드의 앞자리 0을 지우지 마세요.
3. 대시보드 **중장기 → KRX 코스피100 구성목록 등록**을 펼쳐 파일과 기준일을 선택하고 코스피100 파일임을 확인한 뒤 등록합니다.
4. 분석 종목을 비우고 **중장기 탐색 실행**을 누르면 100종목을 순차 분석합니다. 표는 기존 항목을 유지한 채 10행 단위 페이지와 검색을 제공합니다.

UTF-8/EUC-KR CSV와 `종목코드`·`종목명` 열을 지원합니다. 6자리 코드, 중복 없는 정확히 100종목, 기준일(최근 10일 이내, 미래 불가)을 검증합니다. CSV 내용만으로 실제 지수 소속을 자동 인증할 수 없으므로 사용자가 KRX 원본의 지수 선택을 확인해야 합니다. 출처는 **사용자 확인 KRX CSV**로 표시합니다. 임의의 100개 종목 CSV를 등록하지 마세요.

목록은 한국 시간 기준 당일에만 재사용합니다. 다음 날 자동 조회에 실패하면 최근 KRX 목록을 다시 등록해야 하며, 오래된 캐시나 코드의 예전 20종목으로 대체하지 않습니다. 탐색 중에는 구성목록을 변경할 수 없습니다. 작업별 `universe.json`과 결과에 기준일·출처·100종목을 보존하므로 과거 결과의 당시 범위를 확인할 수 있습니다. 이전 결과는 기존 범위 그대로 표시됩니다.

KRX 조회 필드는 공개된 [pykrx KRX 지수 구성종목 구현](https://github.com/sharebook-kr/pykrx/blob/master/pykrx/website/krx/market/core.py)을 참고했습니다. pykrx 신규 설치는 필요하지 않습니다.

## 분석 기준

Yahoo Finance의 재무 지표, 최대 8개 분기의 손익계산서·현금흐름표·재무상태표, 2년 일봉을 순차 조회합니다. 추세/낙폭은 조정 종가를, 거래대금은 비조정 종가와 거래량을 사용합니다. 자료가 없는 종목은 오류 내역에 남기고 나머지는 계속 비교합니다. 뉴스 및 DART 공시 원문 수집은 이 기능에 포함하지 않았습니다.

점수는 조건을 충족하면 해당 가중치를 더하며, 미충족/누락은 0점입니다. 누락에 맞춰 점수를 재정규화하지 않습니다. 자료 충족률도 동일 가중치 기준입니다.

| 조건 | 1~3개월 | 3~12개월 | 1~3년 |
| --- | ---: | ---: | ---: |
| 매출 성장률 > 0 | 15 | 15 | 15 |
| 이익 성장률 > 0 | 10 | 10 | 10 |
| ROE >= 10% | 10 | 20 | 30 |
| 잉여현금흐름 > 0 | 15 | 15 | 15 |
| 부채/자기자본 0~100% | 15 | 15 | 15 |
| 후행 PER > 0, <= 25 | 5 | 5 | 5 |
| PBR > 0, <= 3 | 5 | 5 | 5 |
| 조정 종가 > 200일 평균, 50일 평균 > 200일 평균 | 25 | 15 | 5 |

기존 기준은 60점 이상, 자료 충족률 75% 이상이며 가격 자료가 7일 이내이고 최근 분기 기준일이 200일 이내여야 합니다. 기준일 누락/미래 날짜, KRW가 아닌 가격, 일반기업과 직접 비교하기 어려운 금융/부동산 업종은 추가 확인으로 분리합니다. 해당 종목도 표에서 삭제하지 않습니다. v2부터는 아래 추가 검증도 통과해야 최종 후보가 됩니다.

이 기준과 가중치는 검증된 수익 전략이 아닌 탐색용 휴리스틱입니다. 점수는 예상 수익률이나 매수 신호가 아닙니다. 재무 지표의 공급자 정의/회계기간이 서로 다를 수 있고 업종별 적정 PER/PBR도 다르므로 원 공시와 동종기업 비교가 필요합니다. 당일 1% 목표, 손절가, 청산일은 이 탐색에 적용하지 않습니다.

## 추가 검증 (long-term-v2)

기존 점수와 추가 검증 점수를 각각 100점 만점으로 보존합니다. 순위의 종합 점수는 **기존 60% + 검증 40%**입니다. 과거 v1 결과는 재계산하지 않고 기존 점수로 표시합니다.

| 추가 기준 | 검증 배점 | 조건 |
| --- | ---: | --- |
| 매출 성장 지속성 | 20 | 최근 3분기 각각 전년동기 대비 양수, 최근 분기 성장률이 설정 하한 초과 |
| 영업이익률 | 15 | 최근 4분기 모두 양수이고 최근 분기 이익률이 전년동기 이상 |
| 이익의 현금 전환 | 20 | 같은 최근 4분기 합산 순이익과 영업현금흐름이 양수이고 영업현금흐름 >= 순이익 |
| FCF 지속성 | 15 | 최근 4분기 FCF 합계 양수, 최소 3개 분기 FCF 양수 |
| 유동성·자기자본 | 10 | 최신 분기 자기자본 양수, 유동자산 >= 유동부채 |
| 주식 수 증가 | 10 | 전년동기 대비 보통주 수 증가율이 설정 상한 이하 |
| 낙폭·거래대금 | 10 | 252거래일 최대낙폭과 20일 평균 거래대금이 설정 조건 충족 |

추가 검증 자료 충족률은 70% 이상이어야 하며 기본 검증 점수 하한은 60점입니다. 누락 항목은 0점이고 충족률에서도 제외하며, 부족한 자료를 최근 요약 지표나 LLM 추정으로 대체하지 않습니다.

**중장기 선별 조건**을 펼치면 다음 값을 이번 실행에 한해 변경할 수 있습니다. 실제 사용한 값은 결과와 함께 저장되어 과거 결과 조회 시 확인할 수 있습니다. 단타 설정에는 반영하지 않습니다.

- 후행 PER 상한: 기본 25배, 양수만 허용.
- 최신 분기 매출 YoY: 기본 5% 초과. 전년동기 매출은 양수여야 하며 최신 매출이 음수이면 비교하지 않습니다.
- 부채/자기자본 상한: 기본 100%, 음수는 허용하지 않음.
- 252거래일 최대낙폭 상한: 기본 45%.
- 20일 평균 거래대금 하한: 기본 1억원.
- 확인 가능한 주식 수 증가율 상한: 기본 5%.
- 추가 검증 점수 하한: 기본 60점.

PER·부채·분기 성장률의 필수 값이 없거나 기준에 미달하면 후보에서 제외합니다. 252거래일 가격/20일 거래대금이 부족해 위험 한도를 확인할 수 없는 경우도 제외합니다. 순이익 양수/영업현금흐름 0 이하, 자기자본 0 이하, 확인된 주식 수 증가 상한 초과도 점수와 관계없이 제외합니다.

분기 합산은 최신 분기의 신선도와 70~110일 간격을 검증합니다. 손익·현금흐름·재무상태표는 **같은 분기 말 날짜**끼리만 결합합니다. 연간 자료와 날짜가 다른 현금흐름은 합산하지 않습니다. YoY 비교는 330~400일 간격도 확인합니다. 제공된 분기가 8개보다 적으면 있는 자료만 표시합니다. FCF가 직접 제공되지 않을 때에만 같은 분기의 영업현금흐름에서 설비투자 지출 절댓값을 빼 계산합니다.

주식 수 비교 구간에 분할/병합이 있으면 희석으로 단정하지 않고 자료 부족으로 표시합니다. 자사주/합병 등 증감 사유까지 자동 해석하지 않으므로 공시 확인이 필요합니다. 확인 불가능한 주식 수 항목은 충족률과 점수에 불이익을 주지만 그 항목만으로 반드시 제외하지는 않습니다.

### 동종업종 비교

입력 종목 중 Yahoo의 동일 `industry`·동일 재무 통화·최근 분기 기준일 차이 45일 이내인 다른 종목을 비교합니다. 지표별로 유효한 다른 기업이 최소 2개 있어야 PER/PBR/ROE 중앙값을 제공합니다. 자기 자신, 오래된 자료, 0 이하 PER/PBR은 제외합니다. 비교 회사 코드를 근거에 표시하며 점수에는 반영하지 않습니다. 전체 시장 또는 전체 업종의 순위로 해석하면 안 됩니다.

DCF는 할인율·장기 성장률·사업별 현금흐름 가정을 확보하지 못한 상태에서 목표가를 자동 생성하지 않도록 이번 범위에서 제외했습니다. 배당 지속성·공시상 감사 의견·사업부별 성장률도 현재 수집 자료만으로 확인했다고 표시하지 않습니다.

### 참고 자료

재무제표와 현금흐름을 함께 읽어야 하는 이유는 [SEC의 재무제표 안내](https://www.sec.gov/about/reports-publications/investorpubsbegfinstmtguide)를 참고했습니다. 위 임계값·배점은 SEC 권고가 아니라 이 프로젝트의 사용자 조정 가능한 연구용 규칙입니다. 분기 자료 수집은 [yfinance Financials 문서](https://ranaroussi.github.io/yfinance/reference/yfinance.financials.html)에 따른 `freq="quarterly"` API를 사용합니다.

## LLM 검토

조건을 통과한 상위 최대 5종목을 한 번의 LLM 요청으로 검토합니다. LLM은 이미 수집된 지표의 근거 ID 및 정해진 추가 확인 항목만 선택합니다. 새로운 숫자, 자유서술 주장, 목표가나 주문은 결과로 허용하지 않습니다. 검증 실패/시간 초과 시 정량 결과를 유지하고 실패를 표시합니다. 후보가 없으면 LLM을 호출하지 않습니다.

## 격리 범위

- 코드: `tradingagents/research/long_term.py`, `service.py`, `universe.py`, `quality.py`
- 데이터: `.local/long_term/<요청ID>/request.json`, `status.json`, `report.json`, `universe.json`
- 구성목록 캐시: `.local/long_term/universe.json`
- 캐시: `.local/long_term/cache`
- 상태 API: `/api/research`, 실행/중단: `/api/research/run`, `/api/research/stop`, 구성목록 등록: `/api/research/universe`
- 기존 로그인과 쓰기 요청의 출처/CSRF 검사를 그대로 적용합니다.
- 별도 Python 프로세스로 실행하며 브로커, TradingAgentsGraph, 스케줄러, 단타 학습 메모리, 주문 로그를 호출하거나 수정하지 않습니다.
- 동시 연구는 파일 잠금으로 한 개만 허용합니다. 중복 요청 ID는 재실행하지 않습니다. 100종목 순차 조회를 위해 최대 실행시간은 60분이며 재시작 후 중단된 작업을 자동 복구/재실행하지 않습니다.
- 단타 분석/매매가 이미 진행/대기 중이면 새 탐색 시작을 거절합니다. 연구 중 도래한 단타 예약 작업과 보유 위험 점검은 기존대로 동작합니다.
- 논리적 격리이며 CPU, 메모리, 네트워크, 같은 OpenAI 계정의 쿼터까지 물리적으로 분리되는 것은 아닙니다. 자원 경합이 우려되면 장 종료 후 LLM 미사용 또는 OpenAI로 실행하세요. 종료 시 이미 전송된 API 요청 비용은 취소되지 않을 수 있습니다.

별도 설치나 키는 기본 정량 탐색에 필요하지 않습니다. 프로젝트에 설치된 yfinance를 사용합니다. Yahoo 접근이 차단/제한되면 자료 조회 오류가 표시됩니다. 구현 검증은 합성 데이터와 모의 API를 사용하며 실제 데이터 품질과 API 비용은 실사용 시 확인해야 합니다.
