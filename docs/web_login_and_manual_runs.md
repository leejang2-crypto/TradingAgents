# 웹 로그인과 수동 실행

## 최초 등록

1. Mac의 Finder에서 `TradingAgents/Setup-Web-Login.command`를 더블클릭합니다.
2. ID와 비밀번호를 입력합니다. ID는 영문·숫자·`_.@-` 3~64자,
   비밀번호는 12~256자입니다. 터미널에 비밀번호 입력 문자는 표시되지 않습니다.
3. 기존 실행 중인 TradingAgents를 종료하고 `Start-DryRun.command` 또는
   `Start-Live.command`를 다시 실행합니다. 두 실행기를 동시에 실행하지 않습니다.
4. 기존 Tailscale 대시보드 주소에 접속하고 등록한 ID·비밀번호로 로그인합니다.
   휴대폰 모바일 데이터에서는 Mac과 휴대폰 양쪽 Tailscale 연결이 필요합니다.

터미널에서 등록할 수도 있습니다.

```bash
cd /Users/leejang2/Project/TradingAgents
/Users/leejang2/Project/.venv/bin/python -m tradingagents.monitoring.auth
```

등록 파일은 `.local/config/web_login.json`이며 비밀번호 원문이 아닌 salted scrypt
해시만 저장합니다. 파일 권한은 소유자만 읽고 쓸 수 있는 `600`입니다.
공용 `.env`의 기존 API 자격증명은 변경하지 않습니다. 코드에 공용 기본 비밀번호를
넣거나 최초 비밀번호를 자동 생성하지 않습니다. 이 등록은 사용자가 직접 해야 합니다.

비밀번호를 잊었다면 같은 등록 파일을 다시 실행해 새 비밀번호를 설정하십시오.
기존 웹 로그인 세션은 다음 요청부터 무효화됩니다. 웹 비밀번호 재설정 API는 없습니다.

## 로그인 이후

- 거래 설정 저장, 모니터링, 계좌 조회, 수동 실행은 같은 로그인 세션을 사용합니다.
  별도 모니터·설정 토큰을 입력할 필요가 없습니다.
- 세션은 최대 12시간, 요청이 없는 상태로 1시간 유지됩니다. 열려 있는 대시보드의
  상태 조회도 요청에 포함됩니다. 로그아웃 또는 서버 재시작 시 다시 로그인합니다.
- 비로그인 상태에서는 대시보드, 상태, 설정, 계좌, 로컬 모델 목록을 볼 수 없습니다.
- 기존 API 클라이언트용 `X-Monitor-Token` / Bearer 인증은 호환성을 위해 유지합니다.
  웹은 이를 사용하지 않습니다. 이 토큰을 가지고 있으면 관리 기능에 접근할 수 있으므로
  계속 비밀로 취급하십시오. 브라우저 localStorage에는 인증 정보를 저장하지 않습니다.
- 세션 쿠키는 HttpOnly·SameSite=Strict이며 쓰기 요청은 출처와 전용 요청 헤더를
  검사합니다. 로그인 실패는 IP당 15분에 5회, 서버 전체 30회로 제한합니다.

HTTP 주소는 Tailscale 내부 또는 신뢰할 수 있는 로컬 환경에서만 사용하십시오.
일반 인터넷 포트 포워딩으로 공개하지 마십시오. HTTPS 프록시를 별도로 운영한다면
공용 `.env`에 `TRADINGAGENTS_WEB_SECURE_COOKIE=true`를 설정할 수 있습니다.
이 옵션 자체가 HTTPS를 켜 주지는 않으며, HTTP 주소에서는 쿠키 로그인이 작동하지
않을 수 있습니다. 현재 Tailscale HTTP 접속에서는 이 옵션을 설정하지 않습니다.

인증 설계 참고: [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html),
[Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html),
[CSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html).

## 수동 실행 버튼

분석 탭 상단의 **자동실행 (1회)** 버튼은 저장된 코스피200 후보 선정, 당일 시장자료
재정렬, 상위 후보 LLM 분석, 조건부 매매를 한 회차 실행합니다. 기존 실행 탭의
‘후보 분석 후 매매’와 같은 경로이며 별도의 매매 실행기를 만들지 않습니다.
현재 모드·진행 단계·대기 작업·최근 결과·오류는 버튼 아래에서 확인할 수 있습니다.
단일 종목 입력란을 비워도 전체 후보 자동실행에는 영향을 주지 않습니다.

버튼은 프로그램이 `daily-market` 모드로 실행되고 웹 실행기에 연결되어야 활성화됩니다.
브라우저만으로 종료된 Python 프로그램을 시작하는 기능은 아닙니다. 변경 적용 후 기존
`Start-DryRun.command`를 재시작하고 웹페이지를 새로고침하십시오. 예약 실행 시각과
일시정지 설정은 버튼을 눌러도 바뀌지 않습니다. 이미 작업 중이면 마친 뒤 실행할지,
안전한 단계에서 중단 요청 후 실행할지 선택하며 이미 접수된 주문은 취소하지 않습니다.

먼저 Trading Settings에서 원하는 LLM, 후보 수, 자본·매매 기준을 **설정 저장**합니다.
수동 요청은 접수 순간의 저장된 설정을 고정해서 사용합니다. 이후 설정 변경은 이미
실행 중이거나 대기 중인 요청에 소급되지 않습니다.

| 버튼 | 동작 | 주문 |
|---|---|---|
| 종목 뉴스 수집 | 입력한 국내 종목의 뉴스 자료 수집 | 없음 |
| 후보 종목 선정 | 검색 키워드 기반 뉴스 수집과 후보 순위 저장 | 없음 |
| 종목 분석만 실행 | 입력 종목의 분석, 보고서·경험 기록과 매매 계획 생성 | 없음 |
| 후보 분석 후 매매 | 후보 선정부터 각 종목 분석 및 매매까지 실행 | 실행기 모드에 따름 |

종목 형식은 `005930.KS` 또는 `000000.KQ`입니다. ‘후보 분석 후 매매’와 ‘자동실행 (1회)’는
등록한 구성목록과 저장된 후보 수를 사용하며 단일 종목 입력은 사용하지 않습니다.
통과한 후보가 없으면 신규 분석/매매를 생략하며 다른 종목으로 대체하지 않습니다.
뉴스·후보·분석은 장외에도 실행할 수 있지만 매매는 설정된 정규장 내에서만 가능합니다.
대기 후 시작 시와 주문 직전에 장 시간을 다시 검사합니다.

모의 실행기는 모의 주문만 실행합니다. 실투자 실행기는 시작 시 기존 `--yes` 승인을
요구하며 웹에서 실제 매매 버튼을 누를 때도 확인창을 표시합니다. 웹으로 모의 실행기를
실투자 실행기로 전환할 수는 없습니다. ‘분석만 실행’은 실투자 실행기에서도 주문을
전송하지 않습니다. 분석은 선택한 외부 LLM의 API 사용료가 발생할 수 있습니다.

## 현재 작업이 있을 때

- **중단 후 실행:** 중단 요청을 표시하고 현재 API 응답을 기다립니다. 다음 분석
  단계·자료 요청 및 주문 직전의 점검 지점에서 중단한 뒤 새 작업을 실행합니다.
- **마무리 후 실행:** 현재 작업의 분석·매매 전체를 마친 뒤 새 작업을 실행합니다.
- **취소:** 새 요청을 접수하지 않습니다.
- **대기 실행 취소:** 아직 시작하지 않은 새 요청만 취소합니다. 이미 요청한 현재
  작업의 중단을 철회하지는 않습니다.

실행 대기열은 한 건만 허용합니다. 자동 작업과 수동 작업은 같은 실행 경로를
차례대로 사용합니다. 프로세스를 강제로 죽여 API 요청을 끊는 방식이 아니므로
네트워크 요청 제한 시간이나 긴 자료 수집만큼 중단 대기가 길어질 수 있습니다.

**이미 접수된 주문 취소, 체결 취소, 원상복구는 수행하지 않습니다.** 새 분석 후 매매는
이전 주문과 별개의 추가 거래가 될 수 있습니다. 실제 주문의 `SUBMITTING` 또는
`UNCONFIRMED` 기록이 해결되지 않았으면 새 주문을 차단합니다. Toss 주문 내역과
`.local/live_orders/orders.jsonl`을 대조해야 하며, 불확실한 주문을 자동 재전송하지 않습니다.

‘자동 실행 일시정지’는 새 자동 작업만 막고 현재 작업을 중단하지 않습니다. 수동
버튼은 계속 사용할 수 있습니다. 일시정지는 서버 재시작 후에도 유지됩니다.
별도 보유 관리의 점검·청산은 일시정지되지 않습니다. [보유 관리·청산 안내](position_lifecycle.md)를 참고하세요.
다시 해제하면 기존 09:00·13:00 실행 규칙과 완료 슬롯 검사가 적용됩니다.

수동 매매를 그 시간대 최초로 실행하면 해당 자동 슬롯도 예약하므로 끝난 직후 같은
슬롯의 자동 매매가 추가로 실행되지 않습니다. 이미 실행된 슬롯에서 사용자가 명시적으로
요청한 수동 매매는 새 실행으로 허용됩니다. 오후 슬롯은 별도입니다.

## 기록과 재시작

`.local/monitor/manual_runs.jsonl`에 접수, 시작, 완료·오류·중단, 대기 취소, 자동 일시정지를
기록합니다. 분석 보고서·경험 저장소·주문 기록은 기존 경로를 계속 사용합니다.
중단 전 완료한 종목의 기록도 삭제하지 않습니다.

요청 ID로 중복 접수를 막으며 서버 재시작 시 대기·진행 중 요청을 자동 재실행하지
않습니다. 재실행하려면 로그인 후 새 버튼 요청을 보내야 합니다. 버튼은 모니터가
켜진 `daily-market` 자동 실행기에서 제공됩니다. `--run-mode once` 실행은 기존처럼
작업 후 종료되며 수동 실행 대기열을 제공하지 않습니다.
