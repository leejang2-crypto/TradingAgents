# 당일 청산 · 최대 2거래일 보유

## 기본 운영

`main.py`의 당일 국내 모의/실투자 실행에 LLM과 독립된 보유 관리 실행기를 추가했습니다.
보유 점검은 09:00부터, 후보 분석은 기본 09:20·13:00에 실행하며 보유 점검은 별도 스레드에서 실행됩니다.
분석이 오래 걸리거나 웹의 자동 실행 일시정지를 켜도 보유 관리와 청산은 계속됩니다.
주문 전송은 같은 관리 상태 잠금으로 직렬화합니다.

| 규칙 | 기본값 |
|---|---|
| 보유 점검 주기 | 정규장 중 30초 |
| 신규 매수 중단 | 장 종료 30분 전, 일반 거래일 15:00 |
| 청산 시작 | 장 종료 15분 전, 일반 거래일 15:15 |
| 기본 보유기간 | 매수 당일 청산 |
| 이월 예외 | 사용자에게 종목별로 허용받은 경우만 |
| 최장 보유기간 | 매수일 포함 2거래일 |
| 종목별 익절 | 실제 평균 매입가 대비 +1%, 비용 전 가격 수익률 |
| 일일 손실 제한 | 설정 자본금의 2%, 기본 1천만 원 기준 20만 원 |

휴장일과 다음 거래일은 Toss 국내 장 운영 달력을 사용합니다. 주말만 제외하여 계산하지
않습니다. 실제 정규장 운영 시간과 웹에 설정한 시간의 교집합 안에서만 주문합니다.
거래일 달력을 확인할 수 없으면 새로운 주문을 차단하고 오류를 표시합니다.
단축장·변경된 운영 시간에서는 청산/매수 제한 시각도 앞당겨집니다.

예: 금요일에 매수하고 이월을 허용했다면, 월요일이 정상 거래일일 때 월요일이 2일째입니다.
월요일이 휴장일이면 다음 거래일이 2일째입니다. 추가 매수로 최초 매수일을 다시 시작하지
않으며 이월 보유 종목에 추가 매수하지 않습니다. 전량 청산 후 신규 매수는 새 보유 주기로
기록합니다. LLM의 HOLD 결정만으로 이월을 허용하지 않습니다.

## 웹 설정

실행기를 재시작하고 기존 Tailscale 주소로 로그인합니다.

- **보유 관리 · 청산**: 관리 수량, 최초 매수일, 최대 보유 날짜, 청산 경고, 주문별 누적 체결 수량을 확인합니다.
- **다음 거래일까지 이월 허용**: 매수 당일 청산 시작 전에만 체크할 수 있습니다. 체크하지 않으면 당일 청산입니다.
- 이월 해제는 다음 점검에 반영됩니다. 이미 청산을 시작했거나 보유 주기가 바뀐 경우 이월을 새로 허용할 수 없습니다.
- **Trading Settings → 운영 시간**: 점검 주기와 장 종료 몇 분 전에 청산/매수 제한을 시작할지 저장합니다.
- 보유 관리의 위험 제한은 저장 즉시 다음 점검/주문 검증부터 적용됩니다. 분석 실행에 고정된 LLM 설정과는 구분됩니다.

## 모의투자와 실투자 범위

모의투자는 이 프로젝트의 가상 계좌 체결 기록을 읽어 보유기간을 복원합니다.
기존 주문 의도만 있는 `RECORDED` 로그를 체결로 소급하지 않습니다.
청산에도 기존 가상 계좌를 사용하므로 실제 잔고·수량이 감소하며 가상 체결임을 표시합니다.

실투자는 **TradingAgents 새 실행기가 주문·체결을 확인한 수량만** 기본 관리합니다.
계좌에 같은 종목의 외부 매수분이 있어도 그 수량까지 임의 매도하지 않습니다.
기존 실주문 로그는 계좌 식별 정보가 없으므로 현재 계좌에 자동 귀속시키지 않습니다.

기존 실계좌 보유분도 관리하려면 **기존 실계좌 보유분 편입**에서 종목 코드, 실제 최초
매수일을 입력하고 전량 자동 청산 동의를 체크합니다. 해당 종목의 현재 보유 전량을
편입하며 기한이 지난 보유분은 다음 정규장 점검에서 청산 대상이 됩니다.
최초 매수일은 사용자 확인값으로 기록하고, API가 매수일을 증명했다고 표시하지 않습니다.
이전 원가를 추측하지 않으며 편입 시점 시세부터 전략 손익을 추적합니다.
편입 당일 전략 손익은 관측 시작 기준으로 표시합니다. 종목 가격 수익률은 Toss에서
수량이 일치하는 평균 매입가를 확인한 뒤 별도로 계산합니다.

Toss 앱이나 다른 매매 시스템에서 관리 수량을 바꾸면 불일치가 발생할 수 있습니다.
이 경우 보유 수량보다 많이 팔지 않으며 손익 평가·신규 매수를 차단합니다.
외부 거래와 관리 장부를 확인해야 합니다. 미확인 수량을 자동으로 장부에서 지우지 않습니다.

## 청산과 체결 확인

1. 청산 시 관리 보유량과 실제 보유량·매도 가능 수량을 조회합니다.
2. 매도 가능한 관리 수량 전부를 시장가 DAY 주문으로 전송합니다. 일반 에이전트 SELL도 기존 1주 대신 관리 수량 전량을 대상으로 합니다.
3. 주문 ID를 저장하고 주문 상세 API로 상태·누적 체결 수량을 확인합니다.
4. 부분 체결은 확인된 수량만 장부에서 차감합니다. 이미 반영한 누적 체결량을 다시 차감하지 않습니다.
5. 청산 주문이 90초 이상 미체결이면 취소를 요청합니다. 취소 응답만으로 취소 완료를 간주하지 않습니다.
6. 원주문의 취소·거부 등 종결과 기존 체결량을 확인한 뒤, 다시 조회한 매도 가능 잔량만 새 주문으로 보냅니다.
7. 종목당 하루 매도 주문 시도는 최대 3회입니다. 실패가 지속되면 경고를 표시하고 다음 거래일에 재점검합니다.

15:00 이후 남아 있는 이 실행기의 미체결 매수 주문도 취소를 요청합니다.
외부 주문은 임의 취소하지 않으며 같은 종목에 진행 중 주문이 있으면 신규 주문을 보류합니다.
접수 응답을 잃어 주문 ID를 모르면 `UNKNOWN`으로 남기고 신규 주문을 차단합니다.
그 주문을 자동 재전송하지 않습니다. 프로세스 재시작 후에도 동일한 주문 기록을 사용합니다.

체결 수량과 수수료/세금 확인은 별개입니다. 체결량이 확인되면 수량은 관리하되 비용 자료가
미완성인 동안에는 손익 목표 판단과 신규 매수를 막습니다. 청산 점검 자체는 계속합니다.
`FILLED`는 실제 주문 상세의 수량 검증 후 표시하고, 모의 체결은 `SIMULATED_FILLED`로 구분합니다.

## 종목별 1% 목표

각 종목이 실제 평균 매입가 대비 +1%에 도달하면 그 종목의 관리 보유분만 전량 청산합니다.
다른 종목의 청산이나 계좌 전체 당일 신규 매수 중단을 함께 유발하지 않습니다.
수수료·세금·슬리피지 차감 후 순수익 1%를 의미하지 않습니다.

관리 전략의 당일 손익은 손실 제한과 성과 조회에 계속 사용합니다.
순 체결 현금 흐름(매수·매도 금액 및 확인된 수수료·세금)과 현재 관리 수량의 평가액을
합산하고, 이전 거래일 마지막 관측값과 비교합니다. 외부 보유분·입출금은 전략 수익으로
계산하지 않습니다. 이는 Toss 계좌 전체 수익률 API를 대체하는 계산이 아닙니다.

종목 손절, 정체 청산, 계좌 일일 손실 제한도 함께 적용합니다. 이미 청산을 시작한 종목은
이후 가격 회복이나 재시작으로 청산 결정을 해제하지 않습니다. 시세·원가를 추측하지 않습니다.
처음 실행한 날의 계좌 손실 기준이 불완전하면 관측 시작 이후 손실임을 표시합니다.
**1%는 청산 트리거이지 실현 수익 보장이 아닙니다.** 자세한 설정과 분봉 진입 규칙은
[종목별 단타 전략](intraday_strategy.md)을 참고하세요.

## 실행 유지와 한계

`Start-DryRun.command` 또는 `Start-Live.command`로 계속 실행해 두어야 합니다.
`--run-mode once`는 작업 후 보유 관리도 종료되므로 지속적인 청산 운영에 사용하지 않습니다.
프로그램 종료·Mac 전원 꺼짐·네트워크 단절 중에는 청산할 수 없습니다.
재실행 시 보유 기한이 지났다면 정규장 내 첫 점검부터 청산을 시도합니다.
장외에는 새 주문을 하지 않고 이미 접수한 주문의 체결 확인만 계속합니다.

거래정지, 가격 제한, 매도 가능 수량 부족, 미체결 또는 API 장애로 **당일 또는 2거래일
안에 실제 체결을 보장할 수 없습니다.** 한도를 넘으면 자동 이월 승인으로 처리하지 않고
기한 초과 청산 대상으로 유지합니다. 웹 경고와 Toss 주문 내역을 확인하십시오.
사용자가 자동 분석을 중단해도 보유 관리 청산은 계속됩니다. 전체 중지는 터미널에서
프로그램을 종료하는 것이며, 이미 접수한 주문이 자동 취소되는 것은 아닙니다.

## 기록과 검증

- `tradingagents/brokers/position_risk.py`: 보유 관리·주문 추적·정책 적용
- `.local/positions/paper.sqlite3`: 모의 보유 관리 장부
- `.local/positions/live_<계좌 해시>.sqlite3`: 계좌별 실전 장부
- 기존 모의 체결 장부와 경험 기록은 계속 사용합니다. 실주문 상태는 보유 관리 장부, 기존 `live_orders/orders.jsonl`, 웹의 ‘최근 주문 체결 확인’에 기록합니다. 보유 관리 장부가 주문 추적의 기준입니다.
- 과거 날짜 분석 및 기존 저수준 주문 계획 유틸리티는 유지하며, 지속 운영 정책은 당일 `main.py` 실행 경로에 적용됩니다.

API 명세 확인 기준: [Toss OpenAPI 1.2.17](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json), 2026-09-15.
사용 엔드포인트: 국내 거래일 달력, 보유 자산, 시세, 매도 가능 수량, 주문 생성·상세·취소 및 진행 중 주문 목록.
검증은 합성 브로커 응답과 임시 모의 계좌로 수행하며 실제 주문을 전송하지 않습니다.
