  실행하지 않으며, 시작된 구간은 재시작해도 자동 재실행하지 않습니다.

  분석 실행 주기와 다릅니다. 과거 다중 에이전트 BUY 감시도 같은 분석 주기를 따릅니다.

- 거래일과 개장 변경은 Toss 달력을 사용합니다. 금요일 다음 월요일이 휴장이면
  다음 실제 거래일이 기한입니다. 청산 시작은 기한보다 `liquidation_minutes`만큼 앞당깁니다.
- 거래정지·미체결·통신 장애로 체결을 보장할 수는 없습니다. 미확인 주문은 중복 전송하지

  `carry_exit_minutes=60` (최대 60). 대시보드 시간 설정과 CLI에서 변경할 수 있습니다.
  과거 복기 자료는 당시 저장된 시간 기준을 유지하며 새 자료에는 새 정책을 기록합니다.

적용 시 실행 중인 프로그램을 정상 종료 후 다시 실행하세요. 기존 잔고·주문·분석 이력은

## 2026-10-29: 기본 자동 단타 경로 변경

분석 방식 설명입니다. 실행 시간은 위의 2026-10-30 정책을 적용합니다.
기존 코드는 삭제하지 않았으며 중장기 분석은 변경하지 않았습니다.

- 기본 `--intraday-engine rules-news`: 자동 모의/실거래 및 대시보드 수동 단타 분석에 적용합니다.
  기본 개장 60분 뒤부터 60분 간격으로 후보를 다시 평가합니다.
  장 종료 60분 전부터 신규 매수를 중단합니다. 보유 점검·청산은 별도로 계속됩니다.
- 처리 순서: 등록 코스피200의 **뉴스 후보** → 분봉 순위·계좌/예산 검사 → 상위 설정 개수의
  실제 매수 조건 검사 → 통과 종목만 뉴스 LLM 검토 → 최신 호가·계좌·위험 검사 → 주문.
  200개 전체를 매번 분석하지는 않으며, 한글 별칭이 없는 종목의 뉴스 누락 가능성도 남습니다.
- 거래량 기준은 첫 5분봉을 제외한 최근 최대 6개 완성봉 평균입니다. 최소 2개 비교봉이
  필요합니다. 거래량만 약한 종목은 `WATCH`로 남지만 실제 진입의 최소 1.5배 조건은 유지합니다.
  예산으로 비용 포함 1주를 살 수 없는 종목, 보유/진행 주문/당일 청산 종목은 앞단에서 제외합니다.
- LLM은 최근 24시간의 최신 뉴스 최대 4건을 `catalyst/risk/uncertainty/neutral`로만 분류합니다.
  뉴스 원문은 Python이 붙이며 가격·목표·손절·보유기간은 생성시키지 않습니다. 위험 근거는 HOLD,
  불확실/종목·날짜 불일치/잘린 응답/자료 누락은 REVIEW로 신규 주문을 차단합니다.
- 뉴스 조건을 통과해도 강제 매수가 아닙니다. 주문 직전 동일한 분봉 조건, 비용 반영 손익비,
  호가, 실제 잔고, 기존 주문, 당일 재진입 금지 등을 다시 검사합니다. 이 경로는 과거 BUY를
  30분 동안 감시 큐에 재사용하지 않고 다음 분석 구간에서 새로 판단합니다.
- `hybrid`에서는 대시보드의 **뉴스 분석 역할** 제공자와 quick 모델만 사용합니다.
  기본은 로컬 `qwen3:8b`이고 gemma deep와 번갈아 호출하지 않습니다. OpenAI 전체를 선택하면
  같은 뉴스 검토를 OpenAI로 수행하며 크레딧 소진 시 기존 로컬 전환 옵션이 적용됩니다.
  시장/토론/트레이더/PM LLM 호출과 과거 보고서 본문 주입은 빠른 경로에서 사용하지 않습니다.
- 로컬 호출은 `/api/chat`, `num_ctx=8192`, 출력 최대 600토큰, 입력 UTF-8 최대 6200바이트,
  요청 제한시간 최대 90초입니다. 모델 설치나 Ollama 전역 환경설정 변경은 하지 않습니다.
  너무 긴 입력은 조용히 자르지 않고 차단하며, 뉴스 발췌/선택 범위는 기록합니다.
- 뉴스 후보 수집은 15분 캐시이며 CSV 내용/검색 설정 변경 즉시 무효화합니다. 분봉 검사는
  매 구간 다시 수행합니다. 동일 종목·날짜·모델·뉴스 입력의 검증된 LLM 결과는 최대 10분 재사용하고,
  입력 뉴스가 바뀌면 다시 호출합니다. 개별 종목 뉴스는 기술 조건 통과 시 새로 수집합니다.
- 실행이 분석 주기를 넘으면 겹쳐 실행하거나 지난 구간을 몰아서 실행하지 않습니다. 완료 후 현재 구간을
  평가합니다. 같은 구간의 시작 기록은 재시작해도 재주문하지 않도록 유지합니다. 수동 실행은 별도
  사용자 명령이며 최종 주문 안전장치는 동일합니다.
- `complete_report.md` 옆에 `decision.json`, `intraday_replay.json`을 저장합니다. 원본 분봉·호가·지수,
  설정·뉴스·판정으로 규칙 판단을 재현할 수 있습니다. 주문 직전 재검사 결과는 기존 위험/주문 기록에도
  남습니다. 파일은 `.local/logs/{dry-run|live}/{runId}/reports/{ticker}/` 아래에 있으며 자동 삭제하지 않습니다.
  이 자료는 미래 데이터 없는 규칙 재현용이지 과거 체결/수익을 보장하는 백테스트가 아닙니다.

적용하려면 기존 실행창에서 Ctrl+C로 정상 종료한 후 `Start-DryRun.command`를 다시 실행합니다.
대시보드 **설정 → 단타 매매 기준 → 자동 단타 분석**에서 현재 방식을 선택/저장할 수 있습니다.
기존 방식 검증은 `--intraday-engine multi-agent`로 가능하며 같은 시간 단위 일정에 다중 에이전트 경로를
사용합니다. 직접 `korea-dry-run`/`korea-execute` CLI 시나리오는 기존 단일 종목 경로를 유지합니다.

목표는 여전히 종목당 비용 전 +1%이며 수익 보장은 아닙니다. 비용 0.3%와 손절거리 0.5%이면
손익비는 `(1%-0.3%)/(0.5%+0.3%)=0.875`로 최소 1.0을 못 넘습니다. 거래를 만들기 위해 이 제한을
낮추지는 않았습니다. 상승장에서도 진입·비용 조건이 안 맞으면 HOLD가 정상입니다.

2026-09-15 적용. 과거의 계좌 전체 하루 1% 목표를 폐기하고, **각 종목의 실제 평균
매입가 대비 가격 수익률 +1%**를 익절 트리거로 사용합니다. 수수료·세금 차감 후
순수익 1% 보장이 아닙니다. 예: 평균 매입가 50,000원이면 관측가 50,500원 이상에서
해당 종목의 관리 수량 전량 매도를 시도합니다. 다른 종목은 각각 판단합니다.

## 실행과 설정

실행 중인 프로그램을 정상 종료한 뒤 기존 `Start-DryRun.command`를 다시 실행합니다.
기존 설정 파일에 새 항목이 없으면 아래 기본값이 자동 병합됩니다. 잔고, 체결 이력,
기존 LLM 선택, 이월 승인 정보는 초기화하지 않습니다. 실투자는 `Start-Live.command`를
사용하지만 먼저 모의투자로 진입 보류 사유와 체결 결과를 확인하는 것이 필요합니다.

웹 로그인 후 Trading Settings에서 새 기준을 변경하고 저장합니다. 비율 입력값
`0.01`은 1%, `0.005`는 0.5%입니다. 위험 설정은 다음 보유 점검부터 적용되고,
이미 청산 대상으로 확정된 종목이나 이미 접수된 주문은 설정 변경으로 되돌리지 않습니다.
이미 도달한 당일 손실 제한도 같은 날짜에는 해제하지 않습니다.

| 설정 | 기본값 |
|---|---|
| 종목 익절 목표 | +1%, 비용 전 가격 수익률 |
| 종목 최대 손절 거리 | -0.5%; ATR/직전 저점으로 더 좁아질 수 있음 |

| 지수 하락 제한 | KOSPI 또는 KOSDAQ이 당일 첫 관측 분봉 시가 대비 -1% 이하이면 매수 금지 (첫 1분 누락 예외는 아래 참조) |
| 신호 가격 이탈 제한 | 최신 완성 5분봉 종가 대비 호가 차이 절댓값 0.3% |
| 정체 청산 | 최초 체결 후 90분 경과, 가격 수익률 +0.2% 미만 |
| 연속 손절 제한 | 당일 3개 보유 주기 전량 손절 확인 후 신규 매수 중단 |

기존 보유분과 미체결 매수 주문이 차지하는 자본/예상 손실도 예약하여 새 주문 한도를
차감합니다. 이미 보유한 종목의 추가 매수와 당일 전량 청산 종목 재진입은 금지합니다.
위험 한도는 계산상 상한이며 급변·갭·거래정지로 실제 손실이 이를 초과할 수 있습니다.

## 처리 흐름

### 코스피200 후보 범위 (2026-09-18)

자동 모의/실투자의 후보 선정은 중장기 탭에 등록한 `.local/long_term/universe.json`을 함께 사용합니다. 중장기 분석을 먼저 실행할 필요는 없고 구성목록 등록만 완료하면 됩니다. 200종목 또는 원본 확인을 거친 201종목 전체가 후보 범위이며, 중장기 분석의 상위 추천 5개나 재무 점수는 단타에 전달하지 않습니다.

- 기존 51개 고정 목록을 후보 범위로 사용하지 않습니다. 해당 목록의 이름은 **등록된 구성종목에 한해서만** 뉴스 인식용 별칭으로 활용합니다.
- 기존 시장·테마·선정 신호·위험 신호 검색을 유지합니다. 현재 기본값은 뉴스 후보 상위 20종목을 시장자료로 재정렬한 뒤 통과한 상위 3종목 분석입니다. 구성목록 전체를 매번 LLM으로 분석하거나 종목마다 새 뉴스 검색을 추가하지 않습니다.
- 영문 CSV도 등록명·코드로 매칭하며, 알려진 한글명은 코드 기준 별칭으로 연결합니다. 한글명/별칭이 없는 종목은 한글 기사에서 누락될 수 있으므로 한글 KRX 구성목록을 권장합니다. 해당 수를 대시보드 경고로 표시하며 임의 번역이나 추정 별칭을 만들지 않습니다.

- 목록 없음·손상·만료·뉴스 수집 실패 시 이번 회차의 신규 후보 분석/주문을 건너뛰고 실패 사유를 저장합니다. 뉴스 후보가 0개일 때도 삼성전자나 `--korea-ticker`로 대체하지 않습니다. 다른 종목을 끼워 넣지 않습니다.

### 뉴스 후보의 당일 시장자료 재정렬 (2026-10-22)

자동 모의/실투자 모두 다음 순서로 동작합니다.

`등록 코스피200 → 뉴스 후보 최대 20개 → 당일 시장자료 평가 → 통과 후보 상위 3개 LLM 분석 → BUY 진입 필터`

20개/3개는 기존 대시보드의 저장 후보 수/분석 종목 수 설정을 따릅니다. 뉴스 수집만
수동 실행한 경우에는 시장자료 평가를 하지 않으며, 단일 종목 수동 분석과 중장기 분석은
변경하지 않습니다. 자동 매매의 단발 실행도 오늘 정규장 자료가 있어야 후보를 선정합니다.
과거 날짜를 최신 시세로 대신 평가하거나, 시장자료 실패 시 뉴스 순위로 복귀하지 않습니다.

뉴스 점수 보정:

- 같은 기사 링크가 여러 검색어에 나타나도 1회만 가산합니다. 링크가 없으면 제목과
  발행일로 구분합니다. 같은 기사에 여러 검색 분류가 있으면 위험 분류를 우선하고,
  그 외에는 가장 큰 분류 가중치를 사용합니다. 내용 자체의 호재/악재 판정은 아닙니다.
- 발행 후 24시간 이내 가중치 1, 24~48시간 0.5, 그보다 오래된 기사 0.25입니다.
  시각이 없거나 잘못된 기사도 0.25만 반영하며 미래 기사는 제외합니다. 위험 점수에도
  같은 최신성 계수가 적용됩니다. 시간대 표기가 없는 국내 기사 시각은 KST로 해석합니다.

시장자료 평가는 개장부터 수집한 완성 5분봉만 사용합니다. 회차 전체가 같은 기준 시각과
KOSPI 기준 수익률을 공유하고, 종목별로 다음 조건을 먼저 검사합니다.

- 최소 20분의 연속 분봉 확보, 설정된 거래대금 하한 충족(기본 추정 10억 원).
- 최신 5분봉 거래량이 직전 최대 6개 5분봉 평균 이상.
- 시초가 대비 상승, KOSPI 시초가 대비 수익률보다 강함, 완성봉 종가가 추정 VWAP 위.
- 최근 최대 14개 5분봉 ATR/종가가 종목 목표 수익률의 3배 미만.
- KOSPI 하락 제한(기본 -1%) 및 거래일·정규장·매수 마감 조건 충족.

통과 후보는 아래 점수 합계로 정렬하고 동점일 때 뉴스 순위를 사용합니다.

| 항목 | 최대 점수 | 산식 |
|---|---:|---|
| 상대 거래량 | 30 | `30 × min(거래량 배수 / 3, 1)` |
| 당일 추정 거래대금 | 25 | `25 × clamp(log10(거래대금 / 하한) / 2, 0, 1)` |
| KOSPI 대비 강도 | 25 | `25 × clamp(종목 수익률 - KOSPI 수익률, 0, 0.02) / 0.02` |
| 5분봉 변동성 | 20 | ATR/종가가 목표 수익률까지 증가하면 가점, 목표의 1~2배는 만점, 2~3배는 감점 |

점수는 **비교용 가설이며 수익 확률·예상 수익률이 아닙니다.** 상승 여력이나 +1% 달성을
보장하지 않습니다. 실거래 성과로 가중치를 학습하거나 백테스트로 최적화한 값도 아닙니다.
후보 조건의 거래량 하한은 1배지만 최종 매수는 기존 1.5배 등 더 엄격한 모든 필터를
다시 통과해야 합니다. 호가·잔고·보유분·위험 예산은 주문 직전에 재확인합니다.

조회는 순차 실행하며 KOSPI 봉은 회차 내 공유합니다. 심볼당 최대 12페이지와 누락 구간의
제한적 재조회(최대 2회), 최대 100개
후보, 전체 수집 예산 180초로 제한합니다. 조회 401은 재인증 1회, 429는 아래의 제한적
재시도 후에도 실패하면 추가 후보 조회를 중단하며 403은 즉시 중단합니다.
개별 종목 자료 오류는 그 종목을 제외하며 지수 오류나 전체 제한시간 초과는
회차 전체 신규 분석을 차단합니다. 조회는 남은 회차 예산/매수 제한 시각 안에서만
대기하며 반환 후 예산을 넘겼다면 결과를 사용하지 않습니다. 기존 보유 점검은
별도 스레드에서 계속됩니다. 추가 LLM 호출은 없지만 Toss 조회량은 증가합니다.

대시보드 **분석 → Candidate Ranking**에 기존 뉴스 항목과 함께 단타 점수, 평가 시각,
시장 지표와 제외 사유를 표시합니다. 전체 결과와 세부 항목 점수는 후보 JSON에,
분석 대상으로 선정된 종목의 시장평가도 분석 요약 JSON의 `candidateScreen`에 남깁니다.
재시작 시 기존 실행 파일을 사용하면 적용되며, 기존 계좌/CSV/사용자 설정은 초기화하지 않습니다.

### Toss 요청 제한 대응

- 동일 실행 프로세스의 모든 `TossClient`는 클라이언트 ID와 API 그룹별 속도 제어를
  공유합니다. 서로 다른 스레드/이벤트 루프에서도 적용됩니다. 분봉 대기열과 주문/주문
  확인 그룹은 분리되어 분봉 제한이 주문 그룹을 함께 잠그지 않습니다.
- 로컬 기본 상한은 종목 분봉 초당 4회, 지수 분봉 초당 2회, 현재가/호가 초당 5회,
  주문 초당 5회입니다. 계좌·주문 내역 등은 그룹별 1~2회입니다. 서버의 공식 한도를
  보장하는 값이 아니라 보수적인 자체 제한이며, 더 낮은 `X-RateLimit-Limit` 응답과
  잔여량/재충전 시각을 관찰하면 추가로 늦춥니다.
- 조회 GET의 429는 `Retry-After`(초 또는 HTTP 날짜), `X-RateLimit-Reset`,
  지수 백오프(1초, 2초) 중 긴 시간을 기준으로 jitter를 더해 최대 2회 재시도합니다.
  인증/대기/요청/재시도를 합친 GET 예산은 최대 20초이며 상위 작업의 남은 시간이
  더 짧으면 그 제한을 따릅니다. 서버가 더 긴 대기를 요구하면 조기에 재요청하지
  않고 이번 조회를 중단합니다. 같은 그룹의 다른 클라이언트도 cooldown을 공유합니다.
- 토큰 발급, 주문 생성/취소 POST는 자동 재전송하지 않습니다. 주문 제한 시각은
  속도 제어 대기 후에도 다시 검사합니다. 취소 요청과 조회 예산 만료는 대기 중 확인하고,
  최종 매수 검사 전체는 최대 30초 및 실제 매수 마감까지의 남은 시간으로 제한합니다.
- 완성 분봉은 OHLCV와 연속성 검사 통과 후 최대 30초/128개 스냅샷만 메모리에
  저장합니다. 클라이언트·종목·거래일·완성 5분 경계·지수 여부가 같은 경우에만 재사용하며
  첫 1분 지수 예외의 경고도 보존합니다. 오류·누락 종목·형성 중 봉은 캐시하지 않습니다.
  호가·현재가·잔고·주문 상태는 이 캐시를 사용하지 않습니다.
- 후보별 `assessment`는 `evaluated`(평가 완료), `unavailable`(조회 실패),
  `deferred`(앞선 제한으로 조회 보류)로 구분합니다. 화면/JSON/Markdown에는 평가 수와
  미평가 수, 가능하면 서버 대기 시간에 따른 재시도 가능 시각(표시된 시간대 기준)을
  남깁니다. 재시도 가능 시각은 정상 응답을 보장하는 시간이 아닙니다.
- `rateLimit` 진단에는 그룹/시도 횟수/대기 시간과 제한 관련 응답 헤더 4개만 기록합니다.
  인증 토큰이나 전체 요청 헤더는 기록하지 않습니다. 최종 매수 검사에서 제한에 걸리면
  신규 매수는 보류하고 보유 관리의 `entryChecks`에도 원인을 남깁니다.
- 이 제어와 캐시는 **프로세스 내부 공유**입니다. TossTrading이나 별도 터미널의 다른
  프로세스까지 호출량을 조절하지는 못합니다. 동일 인증정보를 쓰는 다른 프로그램의
  호출이 합산될 수 있으므로 중복 실행을 피하고, 지속적인 429는 호출량을 함께 확인하세요.

공식 기준: [Toss Open API Rate Limits](https://developers.tossinvest.com/docs).

### 진입 조건 대기 (2026-10-21)

- BUY/Overweight 매수 계획이 진입 검사를 통과하지 못한 경우 최대 5종목을 감시합니다.
  HOLD/REVIEW는 감시 대상이 아니며, 매도 계획도 대기 매수로 바꾸지 않습니다.
- 이미 검사한 5분봉은 반복 검사하지 않습니다. 새 완성 5분봉이 생기면 기존 매수 계획에
  최신 시세·호가·거래량·시장 필터·잔고·보유분·위험 한도를 다시 적용합니다. 조건이 모두
  충족되면 주문하고, 제출 이후 미체결·거절·접수 불확실을 이유로 같은 후보를 재주문하지 않습니다.
- 가격 조회는 별도 작업에서 수행하여 느린 분봉 조회가 보유 종목 청산 점검을 막지 않도록 합니다.
  실제 주문 검증과 장부 갱신은 기존 보유 관리 잠금과 체결 확인 경로를 공유합니다.
- 감시 중에는 **추가 LLM 호출이 없습니다.** Toss 시장자료 조회는 증가합니다. 기본 30분
  유효기간 이내에서만 검사하며, 정규장 매수 마감(기본 15:00)을 넘기지 않습니다.
- 설정 변경, 일시정지/중단, 같은 종목의 새 분석, 프로그램 종료/재시작, 유효기간 만료 시
  감시를 취소합니다. 다른 분석/수동 작업이 실행 중이거나 대기 중이면 감시 주문을 보류합니다.
  재시작 후에는 새 분석이 필요하며, 이전 세션의 매수 후보를 자동 복원하지 않습니다.
- 대시보드 보유 관리의 **매수 조건 대기 후보**에서 상태·이유·만료·재점검 횟수를 확인하고
  종목별 취소 버튼을 누를 수 있습니다. 감시 취소는 이미 접수된 주문 취소와 다릅니다.
  접수 주문은 기존 미체결/부분 체결 관리가 담당합니다.

진입 전략은 설정 탭의 단타 매매 기준에서 하나를 선택합니다. 네 전략의 신호를 OR로
결합하거나 여러 전략의 주문을 동시에 보내지 않습니다.

| 전략 값 | 가격 패턴 조건 (공통 거래량·VWAP·위험 필터도 모두 필요) |
|---|---|
| `breakout` | 최신 완성 5분봉 종가가 직전 3개 5분봉 고점을 돌파 |
| `opening_range` | 개장 후 설정 시간의 고점을 이후 봉이 새로 돌파; 직전 봉 종가는 범위 고점 이하 |
| `pullback` | 최신 봉 저가가 VWAP에 닿고 종가는 그 이상이며 양봉·직전 종가 대비 상승 |
| `vwap_reclaim` | 직전 봉 종가가 당시 VWAP 이하이고 최신 양봉 종가가 현재 VWAP 위로 전환 |

장 초반 범위를 5분으로 설정해도 공통 데이터 요건인 최소 20분의 완성 자료가 필요합니다.
기본 +1% 익절, 최대 -0.5% 손절 거리, 90분 정체 청산, 15:15 당일 청산 시도는 유지합니다.
기존 사용자 설정을 덮어쓰지 않으며, 청산 시각은 실제 거래일의 장 운영시간에 따라 조정됩니다.

## 데이터와 제한

- [Toss OpenAPI 1.2.17](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json)
  확인 기준 2026-09-15. 기존 Toss 자격 증명과 pandas를 사용하며 추가 유료 LLM은 없습니다.
- `/api/v1/candles`: 1분봉, 미수정 가격, 요청당 최대 200개, 최대 12페이지로 개장까지 조회.
  종목 봉 timestamp는 **종료 시각**입니다.
- `/api/v1/market-indicators/{symbol}/candles`: KOSPI·KOSDAQ 1분봉. 지수 봉 timestamp는
  **시작 시각**이므로 1분을 더해 종료 시각으로 정규화합니다.
- `/api/v1/orderbook`: 30초 이내 호가만 허용. 매수호가 최대·매도호가 최소를 사용합니다.
- 거래량 없는 구간/누락 분봉을 임의 보간하지 않습니다. 개별 종목은 당일 개장부터 최소
  20분의 연속 자료를 확보하지 못하면 매수를 차단합니다. 429/권한 오류도 우회하지 않습니다.
- 한 페이지의 실제 봉 수가 200개보다 작아도 `nextBefore`를 따라 개장 시각까지
  조회합니다. 반복되거나 미래로 이동하는 커서는 중단합니다. 형성 중인 5분봉 자료는
  수집 결과에서 제외하고, 지수 시작 시각→종료 시각 변환은 정확히 1분만 적용합니다.
- 누락 구간은 그 구간의 시각을 지정해 1회 재조회합니다. 새 5분 경계로부터 30초 이내에
  마지막 1~2분만 빠진 경우에는 1초 간격으로 최대 2회 재조회합니다. 기준 시각을 뒤로
  옮겨 오래된 신호를 통과시키거나 시각을 임의 반올림하지 않습니다. 아래 지수 예외 외에 끝내 누락되거나
  동일 시각의 완성봉 내용이 충돌하면 차단합니다. 조회 한도와 180초 회차 예산은 유지됩니다.
- `최소 완성 분봉 대기`, `분봉 누락`, `분봉 시각 불일치`를 구분하여 표시합니다.
  후보 JSON의 `intradayScreen.marketData` / `dataDiagnostics`, 종목별
  `intraday.dataQuality`에 조회 페이지별 개수·범위·커서와 예상/실제 봉 개수,
  최초/최종 시각, 전체 누락/비정상 시각을 저장합니다. 최종 매수 검사에서 발생한
  같은 오류는 보유 관리 `entryChecks`의 `dataDiagnostics`에도 남깁니다.
- **지수 첫 1분 예외**: KOSPI/KOSDAQ에 한해 재조회 후에도 개장 첫 1분만 없고
  그 이후 최신 완성 5분 경계까지 연속이면 허용합니다. 09:00 개장 기준 정규화된
  종료 시각 09:01 한 개만 없는 경우입니다. 2개 이상, 장중/마지막 누락, 비정상 초,
  개별 종목 누락은 계속 차단합니다. 09:20 이전에는 이 예외도 허용하지 않습니다.
  09:20에는 지수 실제 19개, 개별 종목 20개가 필요합니다. 누락 봉은 생성하지 않습니다.
- 이때 지수 수익률은 첫 실제 관측 봉의 시가(09:01 시작) 기준입니다. 실제 09:00
  시초가 대비 수익률이 아니며 첫 1분의 등락은 반영하지 못합니다. 후보 상대 강도도
  종목의 09:01 시작 봉 시가를 사용해 지수와 비교 구간을 맞춥니다. 종목 자체의
  당일 수익률/VWAP/돌파 기준은 완전한 종목 자료를 사용하므로 바뀌지 않습니다.
  부분적인 지수 첫 5분 묶음을 완성 5분봉으로 사용하지 않습니다.
- 후보 선정과 최종 매수 검사에 같은 예외를 적용합니다. 후보 JSON/Markdown에는
  `marketReference`의 실제 기준/종료 시각과 경고를 기록하고 대시보드 후보 표에는
  비교 기준 시각을 표시합니다. 최종 매수 결과의 `marketReferences`/`warnings`는
  보유 관리의 진입 검사에도 표시합니다. 예외가 허용되어도 다른 매수 조건은 유지됩니다.
- VWAP/거래대금은 `(고가+저가+종가)/3 * 거래량`을 사용하는 **분봉 근사치**입니다.
  틱 기반 정확한 VWAP나 실제 거래대금, 과거 같은 시각 대비 상대 거래량은 아닙니다.
- 시장 필터는 두 대표 지수 기준입니다. 종목별 업종 분류/업종 ETF 자동 매핑은 아직
  없으며, 업종 강도를 분석한 것으로 표시하지 않습니다. 캔들 차트 시각화도 추가하지 않았습니다.
- 가격 익절·손절은 확인된 체결 평균가 기준입니다. 기존 모의/실행기 체결 이력을 복원하며,
  사용자 편입 실보유분은 수량이 일치하는 Toss 평균 매입가를 확인합니다. 원가를 확인할 수
  없으면 경고하고 신규 매수를 차단하지만 시간에 따른 의무 청산은 유지합니다.
- 일일 손익은 기존 전략 현금 흐름과 보유 평가액을 사용합니다. 이전 거래일 기준이
  없으면 관측 시작 기준으로 표시합니다. 이 경우 시작 전 발생 손실을 복원했다고 주장하지
  않으며, 관측 이후 손실에도 일일 손실 제한을 적용합니다.
- 기존 모의 계좌의 실제 체결 비용 설정은 그대로 유지합니다. 위험 계산의 비용 0.3%가
  모의 장부의 수수료/세금을 변경하지 않습니다. 기존 계좌가 비용 0으로 초기화됐다면
  표시 순수익은 실제보다 낙관적일 수 있습니다. 별도의 비용 보정 성과 검증이 필요합니다.
- 프로그램 종료·네트워크 단절·미체결 중에는 목표 가격 체결이나 손실 상한을 보장하지 않습니다.
  `--run-mode once`는 보유 감시도 종료하므로 지속 운영에는 원클릭 실행 파일을 사용합니다.

구현: `tradingagents/brokers/intraday.py`, `entry_watch.py`, `position_risk.py`, `toss_client.py`, `main.py`.
검증: 합성 분봉/호가/브로커와 임시 모의 장부로 데이터 검증, 위험 수량, 부분 체결,
익절/손절, 재시작 및 웹 설정을 테스트합니다. 전략의 실거래 수익성을 검증한 백테스트는 아닙니다.

기존 `--daily-target-return` 및 `daily_target_return` 설정은 이전 실행 스크립트 호환용으로만
보존합니다. 주문 트리거·에이전트 목표에는 사용하지 않으며 `--position-target-return`을 사용합니다.

## 시장 위험 보류와 자료 오류 구분

후보 선정에서 유효한 KOSPI 등락률이 `-market_drop_limit` 이하이면 정상적인 위험 제한으로
처리합니다. 기본값 `0.01`은 **장초 관측가 대비 -1% 이하 신규 매수 보류**이며 변경하지 않습니다.
비교 기준은 전일 종가가 아니라 첫 실제 관측 분봉의 시가입니다. 개장 첫 분봉이 빠진 경우
09:01 기준이라는 경고도 유지합니다.

- 정상 위험 제한: `intradayScreen.status = market-blocked`, `error = null`.
  후보는 `eligible=false`, `watchable=false`, `assessment=market-blocked`로 기록합니다.
  `marketBlockedCount`를 자료 오류인 `unavailableCount`와 별도로 집계합니다.
- `marketGate`에 지수명, 계산된 등락률, 하락 한도, 비교 기준/평가 시각, 첫 분봉 누락 여부를
  저장합니다. 자동 매매 요약에도 같은 필드를 보관합니다.
- 해당 회차는 정상 완료(`ok=true`)이며, 종목 LLM 분석/신규 주문/추가 후보 계좌 조회는 생략합니다.
  대시보드에는 `완료 · 시장 위험으로 신규 매수 보류`와 실제 수치/시각을 표시합니다.
- 누락/잘못된 지수 값, API 429/인증 오류, 잘못된 한도 설정은 여전히 `failed`로 분리합니다.
  매수 보류를 성공한 매매나 체결로 표시하지 않습니다.
- 기존 보유 점검·손절·시간 청산은 독립적으로 유지합니다. 기본 `daily-market` 단타 경로는
  다음 5분 점검에서 지수 제한을 다시 평가합니다. 지수가 기준 위로 회복해도 종목 분봉·뉴스·
  계좌·최종 KOSPI/KOSDAQ 검사를 모두 통과해야 새 매수가 가능합니다.

수정 전 저장된 `failed` 기록은 감사 이력으로 보존합니다. 업데이트된 프로그램을 재시작한 뒤
새로 평가한 회차부터 표시가 바뀌며, 과거 오류 기록을 정상 완료로 덮어쓰지 않습니다.

## OpenAI 크레딧 소진 시 로컬 전환

- 기본값은 자동 전환 켜짐입니다. 대시보드 **Trading Settings > LLM 설정 >
  OpenAI 크레딧 소진 시 Ollama로 전환**에서 변경하고 저장할 수 있습니다.
  CLI에서는 `--no-openai-credit-fallback`으로 끄고 `--openai-credit-fallback`으로 켭니다.
- 적용 범위는 `main.py`의 국내 종목 분석/모의 주문/실주문 및 자동 매매입니다.
  별도 중장기 리서치, `minimal` 예제, 직접 실행한 upstream CLI는 변경하지 않습니다.
- OpenAI 공식 API가 반환한 HTTP 429와 `credit_balance_exhausted` 코드를 함께
  확인한 경우에만 전환합니다. 일반 호출량 제한, 인증 오류, 타임아웃, 모호한
  `insufficient_quota` 및 별도 지출 한도 오류는 자동 전환 사유가 아닙니다.
- 진행 중이던 분석을 버리고 새로운 Ollama 그래프로 해당 종목을 한 번 다시 분석합니다.
  기존 단타 목표, 자료, 계좌 문맥과 위험 검증은 유지합니다. 뉴스 근거 검증과 로컬
  최종 판정 검증을 활성화하며, 뉴스 검증 실패 시 OpenAI로 재전환하지 않습니다.
- 빠른 역할은 저장된 `ollama_quick_model`(기본 `qwen3:8b`), 매니저 역할은
  `ollama_deep_model`(기본 `gemma3:12b`)을 사용합니다. Ollama 서버와 두 모델이
  준비되어 있어야 합니다. 외장 SSD 모델도 현재 Ollama 서버가 인식하면 사용할 수 있습니다.
- 한 번 소진을 감지하면 같은 프로세스/자격 증명 범위에서는 후속 분석도 바로 로컬로
  시작합니다. 크레딧 충전 후 OpenAI로 돌아가려면 프로그램을 재시작하세요.
  재시작 시 소진 상태를 기억하지 않으므로 아직 미충전이면 다시 확인 후 전환합니다.
  기존 OpenAI/역할별 혼합 설정 자체를 덮어쓰지 않습니다.
- `llmExecution`에 요청 제공자, 실제 제공자, 전환 원인과 시각, 시도 결과를 기록합니다.
  경험 DB에는 실제 역할별 모델과 전환 이벤트를 저장하고, Latest Analyses의
  사용 LLM 상세에도 전환 사실을 표시합니다. API 키는 이 기록에 저장하지 않습니다.
- 재시도 범위는 분석뿐입니다. 주문/저장 실패로 분석이나 주문을 재실행하지 않습니다.
  로컬 서버 불가, 모델 미설치, 시간 초과, 분석 검증 실패 시 신규 주문을 진행하지 않습니다.
