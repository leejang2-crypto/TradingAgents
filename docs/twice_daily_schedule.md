# 장 시작·13시 분석과 매매

## 실행 시간

`main.py`와 두 원클릭 실행 파일은 `daily-market` 모드에서 한국 시간 기준으로 동작합니다.

| 회차 | 기본 동작 |
|---|---|
| morning | 09:20부터 13:00 전까지 최초 1회 후보 선정·분석·진입 조건 검사 |
| afternoon | 13:00부터 장 종료까지 최초 1회 후보 재선정·재분석·주문 처리 |

프로그램을 장 시작 전에 켜 두면 보유 점검은 09시, 분석은 09시 20분과 13시에 실행합니다.
분봉 진입에 필요한 완성 봉을 기다리며, 설정 개장 시각을 바꾸면 오전 준비 시각은 개장 +20분입니다.
장중 늦게 켜면 해당 회차를
실행하지만 지난 회차는 소급 실행하지 않습니다. 예: 14시에 처음 실행하면 오후 회차만 실행합니다.
기존 정규장 시간, 주말 및 설정된 휴장일 검사도 유지됩니다. 정규장 종료가 13시보다 빠르면
오후 회차는 실행하지 않습니다. 개장 시간을 13시 이후로 설정하면 오후 회차만 가능합니다.

13시 실행은 스케줄러가 시간을 확인한 뒤 시작합니다(기본 확인 주기 최대 60초).
오전 분석이 13시를 넘기면 병렬로 주문하지 않고 오전 작업이 끝난 뒤 오후 회차를 시작합니다.
장 종료를 넘기면 추가 주문하지 않습니다. Mac이 꺼져 있거나 프로그램을 종료했다면 실행되지 않습니다.

각 회차는 후보 선정, 네이버 뉴스 수집, 에이전트 분석, 최종 주문 계획을 다시 수행합니다.
모의투자는 가상 잔고 기반 체결, 실투자는 Toss 주문 전송 단계로 연결됩니다.
HOLD나 장 종료·분석 실패인 경우 매매 주문이 없을 수 있습니다.

현재 보유 중인 종목 추가 매수와 당일 청산한 종목의 재진입은 차단됩니다.
목표는 계좌 하루 1%가 아닌 종목별 +1% 익절입니다. 분봉/거래량 진입 필터, 손절,
일일 손실 한도 및 위험 기반 수량 계산은 [단타 매매 기준](intraday_strategy.md)을 참고하세요.

## 중복 방지와 기록

- 모의/실전별, 날짜별, `morning`/`afternoon`별 시작·완료·오류 기록을 저장합니다.
- 같은 회차는 재시작하더라도 자동 반복하지 않습니다. 오후 회차는 별도의 실행입니다.
- 이전 하루 1회 기록은 시작 시각(없으면 완료 시각)을 기준으로 회차를 판별합니다.
- 이전 기록의 시각을 판별할 수 없으면 해당 날짜의 두 회차를 모두 예약된 것으로 처리합니다.
- DB 경험 기록과 보고서 실행 ID는 매 분석마다 새로 생성합니다. 뉴스 스냅샷도 덮어쓰지 않습니다.
- 실행 요약 및 모니터 상태의 `scheduleSlot`에서 회차를 확인할 수 있습니다.
- 오전 완료 후 대시보드의 `nextRunAfter`는 13시, 오후 완료 후에는 다음 거래일 개장 시각입니다.

```text
.local/scheduler/auto_paper_daily_runs.json
.local/scheduler/auto_live_daily_runs.json
```

날짜의 `slots.morning`과 `slots.afternoon`이 회차별 원본 기록입니다.
상위 `completedDates`와 날짜의 `status`는 기존 형식 호환용이며, 회차별 실행 여부는 `slots`로 판단합니다.
오류가 난 회차 역시 자동 재전송하지 않습니다. 실주문 오류는 기존 주문 저널로 접수 여부를 확인하세요.

## 기본 LLM

CLI 및 새 웹 설정의 기본 제공자를 `hybrid`로 변경했습니다.
현재 이 Mac에 저장된 제공자 값도 `hybrid`로 변경했습니다. 다른 예산·모델·역할 설정은 유지했습니다.

- 뉴스 분석: Ollama (`qwen3:8b` 기본)
- 다른 역할: OpenAI (저장된 OpenAI quick/deep 모델)

Ollama 서비스가 실행 중이고 설정된 모델이 설치되어 있어야 합니다.
웹에서 제공자를 변경하면 다음 회차부터 적용됩니다. 저장된 설정은 코드 기본값보다 우선합니다.
OpenAI만 사용하려면 웹에서 `OpenAI 전체`를 선택하거나 명시적인 옵션으로 실행하세요.

```bash
cd /Users/leejang2/Project/TradingAgents
../.venv/bin/python main.py --provider openai
```

기존 프로그램을 `Ctrl+C`로 종료하고 `Start-DryRun.command` 또는 `Start-Live.command`를
다시 실행하면 변경된 스케줄이 적용됩니다. 실투자 파일은 실제 주문을 전송할 수 있습니다.
코드 검증에서는 모의 LLM/브로커를 사용했으며 실제 주문을 전송하지 않았습니다.

`--run-mode once`는 계속 단발 실행입니다. 자동 실전 단발 실행도 현재 시간대 회차를 예약하므로
같은 회차의 스케줄 실행과 중복되지 않습니다. 지정 종목 레거시 `korea-execute`는 자동 회차 관리 밖의
명시적 단발 실행이므로 중복 주문 여부를 별도로 확인해야 합니다.
