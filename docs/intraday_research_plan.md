# 단타 매매 기준 조사와 반영 계획

기준일: 2026-11-03. 대상: TradingAgents-validation의 국내 주식 단타 경로.
상태: 1차 비교 기능 구현. 사용법과 정확한 구현 범위는 [단타 전략 비교 안내](strategy_comparison.md)를 따른다.
기존 매매 전략·저장 설정·계좌 비용은 자동 변경하지 않았다. 새 전략은 주문 없는 비교 전용이며 5분 관찰은 기본 OFF다.
시간대 거래량은 기존 장 마감 자료를 사용한다. 과거 자료 일괄 적재, VWAP 개선, 후보 확장, 청산 변경, 주문 전략 전환은 후속 범위다.

## 결론

우선순위는 **비용과 검증 기반 정비 → 시간대 보정 거래량 → 돌파 후 재확인 → 후보 감시 개선 → 시장 국면과 청산 개선**이다.
지표를 모두 필수 조건으로 추가하거나 거래량 문턱만 계속 낮추는 방식은 권하지 않는다.
기존 전략을 대조군으로 유지하고, 새 방식은 주문 없는 비교 관찰부터 시작한다.
종목당 비용 전 +1%는 익절 목표이지 달성 확률이나 하루 계좌 수익률 보장이 아니다.

| 거래량 기준 | 최신 완성 5분봉 / 개장 첫 5분봉을 제외한 최근 최대 6봉 평균 |
| 기존 순위 요소 | 거래량, 거래대금, KOSPI 대비 상대강도, ATR 변동성 |
| 시간 정책 | 신규 매수 10:00 이상 14:30 미만, 후보 분석 60분 간격, 보유 점검 30초 |
| 손익 관리 | 비용 전 목표 +1%, 손절 거리 상한 0.5%, 90분 정체 청산, 15:15 당일 청산 시작 |
| 위험 제한 | 1회 위험 0.2%, 일일 손실 2%, 연속 손절 제한, 보유/진행 주문 자본 예약, 당일 재진입 금지 |
| 복기 | 후보 가격흐름 및 주간 진단 구현. 주간 비교는 기록된 체결의 투자 규모 민감도 분석이며 신규 진입 전략 백테스트가 아님 |
| 비용 차이 | 진입 심사 가정은 왕복 0.3%. 현재 모의 계좌 DB의 수수료·매도세금·슬리피지 설정은 모두 0 |

코드 근거: [진입 규칙](../tradingagents/brokers/intraday.py), [후보 정렬](../tradingagents/brokers/candidate_screen.py),
[보유 관리](../tradingagents/brokers/position_risk.py), [모의 체결](../tradingagents/brokers/paper_account.py),
[주간 비교](../tradingagents/research/weekly_review.py), [현재 운영 설명](intraday_strategy.md).

현재 모의 체결은 최신 가격에 설정된 슬리피지를 적용하고 잔고·수량·지정가를 확인하는 방식이다.
호가 대기열과 시장 참여자의 주문 경쟁을 재현하는 체결 모델은 아니다.
비용 심사와 계좌 손익의 가정이 다르면 전략의 순수익을 잘못 비교할 수 있다.
기존 이력은 보존하고 새로운 비용 프로필의 시작 시점과 버전을 기록해야 한다.

비용 전 목표 1%, 왕복 비용 가정 0.3%, 손절 거리 0.5%이면 현재 식의 손익비는
`(1.0 - 0.3) / (0.5 + 0.3) = 0.875`다. 최소 1.0을 만족하려면 같은 비용 가정에서
손절 거리는 0.4% 이하여야 한다. 숫자를 맞추기 위해 기술적 근거 없이 손절을 좁혀서는 안 된다.

## 조사 결과와 선정

### 같은 시간대 대비 상대 거래량

TradingView의 Relative Volume at Time은 직전 몇 봉이 아니라 과거 거래일의 동일 시간대 봉과 비교한다.
이는 현재 코드의 직전 30분 내외 비교와 다른 지표다.
[공식 계산 설명](https://www.tradingview.com/support/solutions/43000635874-how-do-we-calculate-relative-volume-and-relative-volume-at-time/).

**우선 반영 후보:** 기존 `recent_rvol`을 유지하면서 `time_rvol`을 별도로 계산한다.
예를 들어 11:00 종료 봉은 과거 거래일의 같은 세션 경과 시간에 종료된 5분봉과 비교한다.
과거 20거래일을 목표로 수집하고 최소 10개 유효 표본을 요구하는 안으로 시작한다.
현재 날짜와 미완성 봉은 분모에 넣지 않는다. 거래정지, 누락, 분할 등으로 비교가 불가능하면 미평가한다.
20일/10일은 검증용 설계값이지 출처가 입증한 최적값이 아니다.

처음에는 진입 차단 조건이 아니라 관찰값과 후보 정렬 보조값으로만 사용한다.
기존 1.2배를 자동 완화하거나, 새 지표 하나가 높다는 이유로 다른 안전 조건을 우회하지 않는다.
과거 같은 시간대 거래량이 커도 오늘 매수할 만한 가격 패턴인지 별도로 확인해야 한다.

### 돌파 후 지지 재확인

저항을 돌파한 가격대가 이후 지지 역할을 하는 개념은 기술적 분석에서 쓰인다.
다만 돌파가 반드시 유지되는 것은 아니다.
[Fidelity 지지와 저항 설명](https://www.fidelity.com/learning-center/trading-investing/technical-analysis/support-and-resistance).

**우선 반영 후보:** 신규 선택 전략 `breakout_retest`를 기존 네 전략과 별도로 둔다.
기존 돌파에 조건을 덧붙여 모든 전략을 더 엄격하게 만드는 방식은 피한다.

1. 완성 5분봉 종가가 당시 직전 15분 고점을 돌파하면 기준선과 관측 시각을 고정한다.
2. 이후 최대 3개 완성 봉 안에서 기준선 부근을 재시험하고 위에서 마감하는지 확인한다.
3. 허용 오차는 호가 단위와 ATR로 정하고, 재시험 봉 저점 아래를 기술적 손절 후보로 삼는다.
4. 고정 손실 상한·비용 반영 손익비와 충돌하면 주문하지 않는다. 손절만 억지로 당기지 않는다.
5. 재시험 중 기준선 이탈, 유효시간 만료, 설정 변경, 새 회차 시작은 기존 신호를 무효화한다.

3봉 대기와 허용 오차는 사전 고정한 실험값이다. 잘못된 돌파와 추격 매수를 줄일 가능성이 있지만,
재시험 없이 계속 오르는 종목을 놓치거나 진입이 늦어질 수 있다. 실제 순성과로 비교해야 한다.

### 추세형 VWAP 눌림목

VWAP는 거래량으로 가중한 당일 평균 가격이며, 기울기와 가격 회복 여부를 함께 관찰할 수 있다.
현재 시스템의 OHLCV 기반 VWAP는 실제 개별 체결 기반 값의 근사치다.
[Schwab VWAP 설명](https://www.schwab.com/learn/story/how-to-use-volume-weighted-indicators-trading).

**2차 후보:** 기존 `pullback`을 삭제하지 않고 개선 버전을 비교한다.
최근 완성 봉 기준 VWAP 기울기, 저점 상승 구조, 눌림 중 거래량 감소와 회복 봉의 거래량 증가를 기록한다.
돌파형에는 거래량 확장을, 눌림형에는 눌림 후 회복 구조를 적용하는 방식을 비교한다.
모든 패턴에 같은 순간 거래량 기준을 적용할지부터 실험하고, 검증 없이 전역 기준을 낮추지 않는다.

### 뉴스 외 시장자료로 후보 발굴

비정상적인 거래 활동이 있는 종목을 먼저 추리고 진입 규칙을 적용하는 접근이 연구·실무에서 사용된다.
미국 주식 ORB 연구 저자의 구현 설명도 상대 거래량을 후보 선정에 사용한다.
이 설명은 상업적 서비스 제공자의 사례이며 국내 코스피200 수익성을 입증하지 않는다.
[연구 저자의 구현 설명](https://concretumgroup.com/automating-intraday-strategies-from-manual-complexity-to-algorithmic-precision/).

**2차 후보:** 현재 뉴스 후보 경로를 유지하고, 같은 등록 코스피200 안에서 시장자료 후보를 추가하는 별도 실험군을 만든다.
저비용 일괄 시세에서 거래대금·상승 강도 등 실제 제공 필드를 확인한 뒤 상위 일부에만 분봉을 조회한다.
뉴스 미매칭 종목도 후보가 될 수 있지만, 주문 전 뉴스 위험 검토는 생략하지 않는다.
자료 부족은 긍정 뉴스로 간주하지 않는다.

초기 비교는 뉴스 후보와 시장 후보를 각각 10개씩, 합산 최대 20개로 제한하는 안이다.
등록목록 밖 종목을 넣지 않고 중복을 제거하며, 후보 경로별 누락률과 성과를 따로 기록한다.
뉴스 경로 감소의 영향도 있으므로 기존 뉴스 20개 경로와 독립 비교한다.
당시 제공되지 않은 구성종목·뉴스·시세를 나중에 채워 넣어 과거에 발견했던 것처럼 취급하지 않는다.

### 시장 국면과 업종 동조

**2차 후보:** 기존 KOSPI 상대강도를 재구현하지 않고 시장 국면 정보를 추가한다.
지수의 개장 대비 수익률, 최근 30분 방향, VWAP 기울기 등을 이용해 상승·횡보·하락·자료 부족을 구분한다.
처음에는 분류별 손익만 기록한다. 검증 뒤 상승 국면의 돌파/눌림 전략 선택에 활용한다.
급락 차단과 자료 신선도 검사는 그대로 유지한다.

업종 동조는 신뢰할 수 있는 업종 매핑과 시점별 데이터 확보 이후 후보 순위 보조값으로 검토한다.
전체 구성종목의 상승 비율을 사용할 때는 실제 평가된 종목 수를 분모와 함께 표시한다.
뉴스 상위 20개의 상승 비율을 코스피200 전체 시장 폭으로 부르지 않는다.
국면별 전략을 자동 선택하는 것은 여러 전략 중 하나를 더 선택하는 문제이므로 별도 검증이 필요하다.

### 가격 진행에 따른 청산

**2차 후보:** 현재 90분 정체 청산과 별도로 30분/60분 시점의 가격 진행을 관찰한다.
MFE는 진입 이후 가장 유리했던 가격 움직임, MAE는 가장 불리했던 움직임이다.
MFE가 작고 VWAP를 이탈한 거래가 실제로 더 나쁜 결과를 냈는지 확인한 뒤 조기 청산안을 만든다.
손절을 뒤로 미루거나 손실 종목의 보유기간을 자동 연장하지 않는다.

비용을 반영한 본전 보호와 추적 손절도 비교 대상이지만, +1% 도달 전 정상 변동에 청산될 수 있다.
손절 주문의 트리거 가격은 실제 체결 가격을 보장하지 않으며 지정가 제한은 미체결 위험을 만든다.
이 원칙은 체결 가정의 주의점이며 Toss가 특정 조건주문을 지원한다는 뜻은 아니다.
[SEC 투자자 안내](https://www.investor.gov/introduction-investing/general-resources/news-alerts/alerts-bulletins/investor-bulletins-15).

이를 국내 개별 종목의 10:00~14:30 매수 규칙에 그대로 적용할 수 없다.

## 데이터와 운영 설계

Toss 공식 REST 문서는 조회 시점에 버전 1.2.28이며 시세, 캔들, 종목 참조정보, 섹터 관련 경로를 제공한다.
현재 프로젝트 어댑터가 그 기능을 모두 구현한 것은 아니다. 과거 분봉의 실제 보존기간과 누락률,
필드 의미, 권한, 호출 한도는 구현 전 계약 테스트로 확인한다.
[Toss 공식 OpenAPI](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json).

- 기존 `get_prices` 일괄 조회와 분봉 호출을 재사용한다. 과거 분봉은 장외에 분산 수집하고 장중 일괄 역조회는 금지한다.
- KRX/NXT/통합 시세의 거래소 범위, 세션 경계, 수정 여부를 기록하여 서로 다른 거래량을 섞지 않는다.
- 거래정지·경고·가격제한 정보의 수집 경로를 확인한다. VI 상태의 신뢰할 수 있는 실시간 제공 여부는 별도 확인 대상으로 둔다.
- 보유 점검과 청산이 시장자료 조사보다 우선이다. 기존 429 대기·전체 요청 예산을 공유하고 초과 시 신규 후보를 축소한다.
- 정규장·주문 가능시간·신선도·누락 분봉·잔고·진행 주문·당일 재진입 금지는 모든 실험의 공통 제한이다.
- 후보 재선정은 현재 60분을 유지한다. 선정된 소수 후보의 5분봉 재평가는 우선 주문 없는 관찰 모드에서만 실행한다.
- 5분 감시 주문 활성화는 별도 설정과 승인으로 분리한다. 이는 사용자가 지정한 1시간 매매 주기를 바꾸는 선택이다.
- 선택 후보라도 같은 봉 중복 평가, 오래된 신호 재사용, 재시작 후 무조건 복원, 뉴스 유효기간 우회는 허용하지 않는다.
- 수치 계산은 Python으로 한다. LLM은 현재처럼 뉴스 검토에만 사용하고 전략이나 거래량 임계값을 임의 수정하지 못한다.
- 지표 계산 자체의 LLM 토큰 증가는 없다. 통과 후보가 늘면 뉴스 호출은 늘 수 있으므로 회차/일별 호출 예산과 실제 사용량을 기록한다.
- 분봉/호가/설정/판정/체결 가정/구성목록 해시를 외장 드라이브의 별도 연구 폴더에 저장한다. 경로는 `/Volumes/External/TradingAgents/strategy_research`이며 1차 구현에서 생성했다.
- 외장 저장소가 없으면 신규 실험을 중단하고 경고하되 기존 보유 관리·청산을 중단하지 않는다.

## 단계별 반영 계획

| 단계 | 구현 범위 | 완료 기준 |
| --- | --- | --- |
| 0. 대조군과 비용 | 현재 1.2배 설정·코드·목록 해시 고정, 모의 비용 프로필 버전 관리, 진입 비용/체결 비용 구분 표시 | 기존 계좌·이력 무변경, 각 결과의 비용 가정 식별 가능 |
| 1. 기록과 재현 | 주문 없는 전략 비교 실행기, 데이터 커버리지, 실제/가상 체결 구분, 외장 저장 | 동일 입력·설정으로 동일 판정, 누락·미래 자료 차단 |
| 2. 거래량 실험 | 최근 거래량과 동일 시간대 거래량 병행, 과거 자료 장외 적재 | 표본 부족 미평가, 기준 시점 이후 데이터가 계산에 들어가지 않음 |
| 3. 진입 실험 | `breakout_retest`, 기존/개선 눌림 비교, 선택 후보 5분 관찰 | 주문 0건인 비교 모드, 중복 신호·만료·설정 변경 처리 검증 |
| 4. 후보와 청산 | 시장자료 후보, 국면별 비교, 진행도 청산을 각각 독립 실험 | 구성목록 및 API 예산 준수, 개별 변경 효과 분리 |
| 5. UI와 전환 | 전략별 비교표, HOLD 사유, 비용·자료 품질, 버전 적용·되돌리기 | 모의/실전 설정 분리, 사용자 승인 전 기본 전략과 실전 불변 |

개발 우선 범위는 0~3단계다. 4단계의 모든 후보를 한꺼번에 활성화하지 않는다.
백테스트 결과가 좋다는 이유만으로 실거래를 자동 전환하지 않는다.

## 검증 방법과 적용 조건

1. **대조군 고정:** 현재 저장 설정을 기준으로 한다. 1.5배는 과거 설정 비교용으로만 별도 기록한다.
   거래량 개선, 재시험 전략, 감시 주기 변경을 동시에 적용하지 않고 한 번에 하나씩 비교한다.
2. **사전 실험 등록:** 전략별 수식·파라미터·비용·기간·실험 수를 먼저 고정한다. 실패한 실험도 저장한다.
   많은 변형을 같은 자료에 맞추는 것은 과최적화 위험이 있다.
   [Bailey 등 과최적화 연구](https://www.davidhbailey.com/dhbpapers/overfit-tools-at.pdf).
3. **시점 일치:** 과거 당시 구성목록과 최초 후보 발견 시각을 사용한다. 뉴스는 최초 수집 시각 이전에 존재했다고 가정하지 않는다.
   학습/검증 날짜를 시간 순으로 분리하고 검증 결과로 재조정하면 다음 미사용 구간에서 다시 평가한다.
4. **체결 현실성:** 신호 봉의 종가로 즉시 체결됐다고 가정하지 않는다. 확인 지연 뒤 이용 가능한 호가를 사용한다.
   호가 기록이 없으면 보수적 체결 가정임을 표시하고 실체결처럼 합산하지 않는다.
   한 봉 안에서 목표와 손절을 모두 건드렸다면 순서를 미상으로 기록하고 낙관적인 승리로 처리하지 않는다.
5. **계좌 재현:** 정수 주식 수, 사용 가능한 현금, 수수료·세금·스프레드·슬리피지, 동시 보유,
   진행 주문 자본, 부분 체결·취소·미체결·거래정지를 반영한다. 스프레드와 슬리피지는 중복 차감하지 않도록 정의한다.
6. **평가 지표:** 비용 후 기대손익, 승률과 평균 이익/손실, Profit Factor, 평가손익 포함 최대 낙폭,
   목표 도달률, MFE/MAE, 신호→주문 지연, 미체결률, HOLD로 피한 손실과 놓친 기회를 함께 본다.
   최고가가 +1%를 넘었다는 사실만으로 실제 수익 기회로 계산하지 않는다.
7. **표본:** 우선 최소 20거래일과 전략별 50개 완결 거래를 운영상 1차 점검 문턱으로 제안한다.
   이 수는 통계적 충분성 보장이 아니다. 표본이 부족하거나 특정 하루·종목에 수익이 집중되면 기간을 연장한다.
   가능한 과거 자료로 선행 검증한 뒤 미사용 실시간 모의 기간을 두고, 일자 단위 의존성을 고려해 불확실성을 표시한다.
8. **적용:** 미사용 구간에서 비용 후 성과 개선이 확인되고 낙폭·미체결·데이터 오류가 허용 범위 이내인지 판단한다.
   비용 상승 스트레스에서도 결론이 유지되는지 보고, 개선이 불명확하면 기존 전략을 유지한다.
   모의 적용 후에도 실전은 별도 승인한다. 버전 전환은 진행 주문과 기존 보유분의 관리 규칙을 임의 변경하지 않는다.

최초 화면에는 현재 전략과 후보 전략의 거래 수·순손익·낙폭·자료 커버리지 및 비용 가정을 나란히 보여준다.
사용자는 거래 횟수가 늘었다는 이유가 아니라 동일한 위험 한도에서 비용 후 결과가 개선됐는지 보고 선택한다.
