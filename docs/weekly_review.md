# 휴장일 주간 복기

## 실행 방법

기존 `Start-DryRun.command` 또는 `Start-Live.command`를 재시작하고 계속 켜 두면 됩니다.
`main.py`의 `daily-market` 실행기가 한국시간 오전 9시 이후 거래소 달력을 확인합니다.
주말뿐 아니라 평일 공휴일도 실제 정규장 유무로 판정합니다. 달력 API가 실패하면
휴장이라고 추정하지 않고 15분 뒤 재확인합니다. 매매 일시정지 중에도 읽기 전용 복기는 가능합니다.

- 대시보드 **주간 복기 > 복기 실행**: 최근 완료된 5거래일을 수동 복기합니다.
- 정규장 진행 중이면 전 거래일까지, 장 마감 5분 후에는 당일까지 포함합니다.
- 자동 실행은 휴장일에만 동작합니다. 정상 영업일은 다음 날 9시에 재확인합니다.
- 휴장일에는 6시간 간격으로 자료 변경을 확인하되 같은 자료·설정은 동일 결과를 재사용합니다.
- 프로그램 종료/절전 중에는 실행되지 않습니다. 별도 OS 예약 작업을 설치하지 않습니다.
- 설정의 **휴장일 주간 자동 복기** 또는 `--no-weekly-review`로 자동 실행을 끌 수 있습니다.
- 수동 실행은 단타 분석을 취소하거나 주문하지 않습니다. 보유 관리도 그대로 유지됩니다.

## 자료와 통계

최근 5거래일의 일별 복기 원본과 최근 90일 이내 저장된 일별 기록을 사용합니다.
같은 날짜의 여러 버전은 최신 하나만 선택하며 원본 입력 해시와 체결을 재검증합니다.
손상된 최신 버전을 이전 버전으로 조용히 대체하지 않습니다.

일별 외장 저장이 누락되면 로컬 분석/학습 기록과 체결 장부로 진단만 시도하고 `partial`로 표시합니다.
기록이 없으면 무거래일로 확정하지 않습니다. 과거 후보군은 당시 저장된 구성목록만 사용하며
현재 코스피200이나 현재 설정을 과거에 소급 적용하지 않습니다.

집계 항목:

- 검증된 완결 매매의 비용 반영 손익, 승률, 평균 이익/손실, 이익합계/손실합계 비율
- 진입 전략, 시간대, **진입 시점까지**의 KOSPI 장초 관측가 대비 흐름별 손익
- HOLD 이후 기존 규칙의 차트 구간에서 목표/손절 중 무엇이 먼저 도달했는지
- 전략별 목표·손절·청산·정체·동일 봉 순서 불명 구간 수
- 실제 보유 구간의 완성된 분봉으로 관측한 최대 상승폭/하락폭과 실제 순수익률
- 주문 처리 상태, 오류 분류, 기록된 시작~결과 시간, 뉴스 모델 사용 횟수
- 당시 코스피200 구성목록 기준일·종목 수·해시, 누락 자료와 검증 실패

HOLD 기회·손실 회피 항목은 후보-일 단위로 집계하며, 한 후보에 두 종류의 구간이 모두 있을 수 있습니다.
차트 구간은 계좌 제약과 당시 주문 가능성을 모두 재현하지 않습니다. 후행 상승폭과 목표 도달 구간 수를
실제 수익이나 승률로 해석하면 안 됩니다. 완결 매매 손익 또한 계좌 총수익률이 아닙니다.

LLM 청구액, 뉴스의 인과적 기여, 저장되지 않은 탈락 종목의 성과, 계좌 최대 낙폭은
현재 자료만으로 확정할 수 없으므로 평가 불가로 표시합니다.

## 개선안과 승인

이번 버전의 적용 가능한 제안은 **같은 규칙의 신규 투자금/매매 위험 예산 75% 제한** 하나입니다.
진입 패턴 자동 교체, 수익 목표·손절·매수 시간·청산 기한 완화, 여러 파라미터 중 과거 최고 수익 선택은 하지 않습니다.

1. 동일 설정 지문의 실제 완결 매매 날짜를 시간순으로 나눕니다.
2. 앞 약 2/3 날짜를 학습 구간, 나머지를 후행 검증 구간으로 분리합니다.
3. 학습 구간 10건 이상·3일 이상, 순손실, 승률 40% 미만일 때만 축소안을 제안합니다.
4. **모의 비교**는 후행 구간의 기존 수량과 75% 수량을 비교합니다. 두 경우 모두 설정된
   모의 자본금(기본 1천만원), 초기 보유 0으로 시작합니다. 모드별 자료를 섞지 않습니다.
5. 정수 수량, 시간순 현금·동일 종목 보유 제한, 기록된 가격·시각·수수료·세금을 사용합니다.
   축소 수량 비용은 비례 산정 후 원 단위 올림하며 마지막 분할 매도는 잔여 수량을 정리합니다.
6. 검증 구간 10건·3일 이상, 같은 거래 모두 비교 가능, 미완결 보유/자료 누락 없음,
   다른 규칙의 검증 구간 보유 없음, 기존 규모 축소가 적용되지 않은 표본이어야 합니다.
   학습/검증 경계를 걸치는 보유는 제외하고 승인을 차단합니다.
7. 후행 구간도 손실이면서 축소안의 손실이 줄고 실현 손익 기준 낙폭이 비악화여야 승인 가능합니다.
8. **개선안 승인**에서 해당 모드 적용을 직접 확인해야 합니다. 복기·비교만으로는 적용되지 않습니다.

기존 과거 주문에 주간 검증용 전체 설정 지문(분봉 규칙·자본 배분·LLM 배치)이 없으면
손익 진단에는 표시하되 개선안 표본에는 넣지 않습니다. 업데이트 이후 새 주문부터 지문을 기록합니다.

이 비교는 **과거 체결 기반 수량 민감도 분석**입니다. 동일 진입/청산을 고정하며, 정확한 호가·체결 대기·시장 충격·
새 신호·계좌 전체 손익을 재현한 전략 백테스트가 아닙니다. 실현 손익 기준 낙폭도 계좌 평가액 최대 낙폭이 아닙니다.
기준 충족은 통계적 유의성이나 전략 우월성의 증거가 아닙니다. 규모 축소는 이익도 줄일 수 있습니다.
75% 수량이 0주가 되거나 현금이 부족해 비교 거래가 달라지면 승인을 차단합니다.

실투자는 자체 모드의 검증 자료와 명시적 승인이 필요합니다. 모의투자 결과를 실투자 정책으로 자동 복사하지 않습니다.
충분한 실투자 표본이 없으면 승인 불가입니다.

승인 이후 신규 BUY에만 반영됩니다. 원자료 마지막 날짜 다음 날부터 7일 이내 유효하며,
규칙·자본·배분·위험 한도가 변경되면 미적용됩니다. 기존 일별 복기 축소와 겹치면 배수를 곱하지 않고
더 작은 배수 하나를 적용합니다. 주문의 전략 근거에도 승인 버전을 기록합니다.

**적용 원복**은 현재 주간 개선안을 해제합니다. 신규 매수 규모가 원래 설정으로 돌아갈 수 있으므로 확인창이 표시됩니다.
일별 복기 제한은 별도로 유지하며 이전 주간 정책을 자동 재활성화하지 않습니다.
자동 복기 스위치를 끄는 것은 이미 승인된 정책 원복과 별개입니다.

## 로컬 요약과 비용

통계·제안·비교에는 LLM을 사용하지 않으며 OpenAI 토큰 비용이 추가되지 않습니다.
**로컬 요약**을 누르면 기존 Ollama quick 모델이 Python 산출 사실 중 중요 항목의 번호만 선택합니다.
화면에는 해당 원문을 그대로 표시하므로 모델이 수익률이나 매수 판단을 새로 작성하지 않습니다.
외부/클라우드 모델, 프록시, 리다이렉트는 허용하지 않습니다. 실패해도 원래 복기와 매매는 유지됩니다.
거래일 달력 GET 호출만 추가되며 전체 200종목 뉴스/시세를 새로 수집하지 않습니다.

## 저장과 알림

```text
/Volumes/External/TradingAgents/weekly_review/<mode>/<account>/<마지막 거래일>/<내용 해시>/
  review.md
  review.json
  evidence.json
  manifest.json
  comparison.json  # 모의 비교 시
  summary.json     # 로컬 요약 시
```

로컬 캐시와 승인 이력은 `.local/weekly_review/<mode>/<account>/`에 저장합니다.
모드·계좌를 분리하고 `.env`나 API 키를 포함하지 않습니다. 생성 파일 0600, 폴더 0700이며 Git에서 제외됩니다.

외장 드라이브가 없으면 내부 SSD에 대체 경로를 만들지 않습니다. `Setup-Postmarket-Storage.command`로
일별·주간 폴더를 함께 준비할 수 있습니다. macOS 이동식 볼륨 권한 요청이 나오면 허용하세요.

기존 텔레그램 **복기 알림**이 활성화되어 있으면 새 결과 완료 시 알림을 보냅니다.
동일 결과 재조회에는 보내지 않으며 API/저장 실패는 오류 알림으로 전달합니다.
승인/원복은 대시보드의 버전과 현재 적용 상태로 확인합니다.
